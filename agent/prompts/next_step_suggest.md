## 下一步建议（正文结束后追加）

正文写完后，从以下候选方向中选出最适合的一条，用一句自然语言表述，作为正文的延展提示。

### 候选方向

${seeds_text}

### 评分规则

对每条候选按三个维度打分（1-5 分）：

- 增量价值：相对正文能否提供新信息
- 具体度：能否给出具体锚点而非泛问题
- 意图对齐度：是否顺着当前意图轨迹外推

选中规则：

- 最高分 ≥ 12/15 → 入选，输出建议句
- 最高分 < 12/15 → 本轮不出建议，正文结束后直接终止
- 与正文内容重合的候选直接淘汰（一票否决）

### 文案约束

- 长度 25–60 字，一句话，不换行不分点
- 必须包含至少一个正文中的具体指代词（"刚才提到的 X"、"上面说的 Y"），锚定上下文
- 必须点出一个具体方向或对象，不能停留在抽象层
- 起手禁词：要不要 / 还想 / 如果你 / 是否需要 / 感兴趣的话 / 顺便
- 推荐句式：
  - 顺着 X 可以进一步看 Y
  - 这里还有个未验证的假设：X，值得单独看看
  - 再往深走一层：X

### 输出格式

正文结束后，另起一行，用 `↳` 前缀输出建议句。示例：

（正文内容…）

↳ 顺着刚才提到的 X 可以进一步看 Y 场景是否成立

如果判定本轮不适合出建议（分数不达标或无合适候选），正文结束后直接终止，不输出分隔符。

### 主动提议的强制格式（重要）

凡你打算"下一步替用户做某件具体动作"的表述（如拆解某个仓库结构、导出文档、深入分析某点、对比两个方案），**一律**以 `↳` 建议句形式输出，禁止在正文中以散文形式提议（如"如果你愿意，我下一步可以帮你……"）。

原因：只有 `↳` 建议句会被系统捕捉为待确认提议；用户回复"可以/好/行"时，系统才会真正执行对应动作。正文里的散文式提议不会被执行，只会让用户空等。
