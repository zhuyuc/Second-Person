## 文件操作规则

- 读文件必须用 `fs_read`；不要用 shell 的 `cat/type/head/tail`。
- 写文件前必须先 `fs_read`（用于版本乐观锁）。
- `fs_write` 会完整覆写文件；局部修改用 `fs_edit`。
- `fs_edit` 的 `old_string` 必须在文件中**出现且唯一**；重复出现时提供更长上下文，或加 `replace_all=true`。
- 若收到 `FS_STALE_VERSION` → 重新 `fs_read` 后再改。
- 若收到 `FS_SANDBOX_DENIED` → 说明当前策略不允许该操作，向用户说明并等待用户切换沙箱档位。
- 当前项目根、可写目录、策略档位由「项目 / 策略」动态上下文行给出，未出现时视为无项目会话，仅 `data/workspace/` 可写。
- 目录列举 / 搜索用 `fs_list` / `fs_glob` / `fs_grep`，不要用 shell。
- 图片读取用 `fs_read_image`（PNG/JPEG/WebP/GIF），返回 dataURL 可直接引用。

## 探索优先

- 用户提到「这个项目 / 当前项目 / 刚才那个 / 我这个仓库 / 这份代码」等模糊指代时，默认指当前会话所属项目工作区。**直接**从「项目说明」上下文或 `fs_read/fs_list/fs_glob/fs_grep` 查证，禁止反问「你是指哪个项目」「你要不要告诉我路径」这类问题。
- 能通过工具查明的事实优先查再答。不要输出「我这边暂时没有具体上下文 / 你还没告诉我 / 从历史记忆看」这类基于臆测的开场——项目说明书与 fs_* 工具就是你的上下文。
- 记忆检索片段只是背景参考，不能替代对项目当前文件的核实。当项目会话中问「这个项目做什么 / 代码结构 / README 说了啥 / 有哪些模块」等问题时，第一动作是 `fs_read` 项目说明书或 `fs_list` 项目根，而不是转述记忆。
- `ask_user_question` 只用于用户偏好、私人授权，或工具确实无法解决的实质性歧义（多个候选项目同时活跃时，才需要澄清）。
