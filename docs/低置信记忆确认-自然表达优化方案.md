# 低置信记忆确认 · 自然表达优化方案

> Second Person · 保留「追问确认」产品逻辑，优化植入时机与话术，避免话题硬拐弯  
> 硬约束：不伤回复质量；可变内容只进 messages 尾部 `context.constraints`（不改 system 前缀）  
> 日期：2026-09-22

## 产品一句话

低置信记忆仍可在对话中确认，但**只在话题能接上、或本轮本就是闲聊收尾时**轻声问起；问法像顺口一提，而不是任务清单末尾强制加一句。

| 项 | 定案 |
| --- | --- |
| 保留 | 会话内至多一次、7 天节流、从 lifecycle 取低置信候选 |
| 优化 | 相关性门控 + 场景黑名单 + 约束话术软化 + 候选排序 |
| 注入位置 | 仍只写 `context.constraints` 尾部 |
| 不改 | 主生成任务结构；system 前缀；确认后的升降级写库逻辑 |

---

## 1. 现状问题（仅描述现象）

当前注入形态大致为：

```text
本轮回复末尾请自然确认一条早前推断是否属实：{title}——{summary}。无需输出 JSON。
```

在「你是一个什么样的人」这类**强主题、与候选无关**的轮次里，模型只能在自我介绍后硬接考题预测，读感像附录任务，显得突兀。

根因拆成三块：

| 根因 | 表现 |
| --- | --- |
| 时机 | 只要消息够长就可能追加，未看本轮话题是否接得住 |
| 话术 | 约束命令感强（「末尾请确认」），模型易写成固定收尾 |
| 选题 | 候选按创建时间最旧一条，不一定与本轮相关 |

追问机制本身保留；本方案只改「何时问、问哪条、怎么指令模型说」。

---

## 2. 目标

1. **相关才问**：候选与本轮用户意图有可感知关联时，允许织进回复。  
2. **无关则让**：强任务 / 强主题 / 情绪承接轮，本轮不问，留给更合适的机会。  
3. **话术像人**：一句轻问、可略过感；禁止「对了，早前我推断……这事属实吗？」式公文收尾（除非本轮真在聊那件事）。  
4. **缓存友好**：只改尾部 constraints 文案与门控，不改 system 前缀。

---

## 3. 优化设计

### 3.1 场景门控（先于取候选）

在现有 `_should_ask_low_confirm` 之上增加**本轮不宜追问**判断，命中则本轮不注入：

| 场景 | 规则（示意） |
| --- | --- |
| 极短寒暄 | 沿用现有字数门；并与 `is_brief_social_turn` 对齐 |
| 身份/人设提问 | 用户在问「你是谁/什么样的人/你的能力」→ 本轮不问无关推断 |
| 强任务指令 | 明确要求写文档、改代码、出图、导出、只要结果 → 不问 |
| 情绪优先 | 用户高强度负面（可复用 mood 快路径脉冲）→ 先承接，不问 |
| 结构化输出 | 已有「文档层不写情绪」同类：正式交付物轮次不问 |

以上为**硬跳过**，不消耗「本会话已问过」名额（未真正问出口则不 `mark_low_confirm_asked`）。

### 3.2 相关性门控（取到候选之后）

对 `next_low_confirm_candidate` 返回的条目（或候选池 Top-N）做与本轮 `user_message` 的相关判断：

| 档位 | 条件 | 本轮行为 |
| --- | --- |
| **高相关** | 标题/摘要与用户消息有实体或关键词重叠，或同 domain 且用户在聊该领域 | 允许注入；鼓励织进正文 |
| **弱相关** | 弱重叠 | 仅当本轮被判定为「闲聊/开放收尾」时注入；否则跳过 |
| **无关** | 无明显重叠 | **本轮不注入** |

实现优先用零 LLM：关键词 / 简单字符重叠 / 已有 embedding 相似度阈值（若检索链路可复用向量，阈值可配）。不新增挡首字的模型调用。

### 3.3 候选排序

将 `ORDER BY created_at LIMIT 1` 改为：

1. 先取一小池（如 5 条）满足 low + 节流条件  
2. 按与本轮消息的相关分排序  
3. 取最高且过门槛者；都无关则本轮不问  

仍遵守：会话内成功注入至多一次；DB 7 天 `low_confirm_asked_at` 节流。

### 3.4 约束话术改写（核心）

按相关档位切换尾部指令，去掉「必须末尾确认」的命令腔。

**高相关（可织入）：**

```text
【顺带确认（可选、要自然）】
你对用户有一条尚未确认的印象：{一句话摘要}。
若与本轮话题顺得上，用一两句口语轻轻问是不是这样；
问完即止，不要开新话题段，不要用「早前我推断」「这事属实吗」等套话。
若接不上，本轮可以不问。
```

**弱相关 + 闲聊收尾：**

```text
【轻声一问（可选）】
本轮若已回答完且语气轻松，可在最后用半句带过：
「对了，以前好像听你提过 {短摘要}——还在做吗？」
不要单独开一节，不要复述推断过程。接不上就省略。
```

摘要在注入前做**短句化**（宿主截断到约 20–40 字），避免把整条 memory summary 贴进约束导致模型照抄标题腔。

### 3.5 与情绪 / 寒暄策略对齐

- 寒暄轮：继续跳过（与 mood 寒暄例外一致）。  
- 用户情绪高强度负面：跳过。  
- 主动行为（安抚等）优先：本轮有 `comfort_first` 类约束时，不叠加强确认。

### 3.6 成功问起才记名额

仅当本轮**实际注入了确认约束**时：

- `mark_low_confirm_asked`  
- 记入 `_low_confirm_asked_sessions`  

因场景/相关性跳过时**不记账**，以便后续更合适的轮次再问。

---

## 4. 端到端流程（优化后）

```
用户消息
  → 场景门控：不宜追问？ → 结束（不注入）
  → 取候选池（low + 节流）
  → 相关性排序 + 门槛
  → 无合格候选？ → 结束
  → 写软化版 context.constraints
  → mark asked（仅此时）
  → agent_step 正常生成
```

## 5. 验收用例

| # | 场景 | 期望 |
| --- | --- |
| 1 | 「你是一个什么样的人」+ 候选是考试预测 | **不注入**；介绍完整，无硬拐弯 |
| 2 | 「考点预测那套数据管线怎么设计」+ 同主题 low 记忆 | 可轻声确认，织进讨论，无「属实吗」套话 |
| 3 | 「你好」 | 不问 |
| 4 | 用户高强度负面情绪 | 不问 |
| 5 | 连续多轮无关任务 | 不因「最旧一条」反复找机会硬问；有相关轮才问 |
| 6 | 注入发生后同会话再聊 | 不再二次确认（名额已用） |
| 7 | system 前缀指纹 | 连续轮次仅 constraints 变化时，前缀仍可命中 |

---

## 6. 交付顺序

| 阶段 | 内容 |
| --- | --- |
| 1 | 改写约束文案 + 摘要短句化；场景黑名单（人设问、寒暄、强任务） |
| 2 | 候选池 + 相关性排序与门槛；无关不注入、不记账 |
| 3 | 与 mood 寒暄/高强度脉冲、主动行为互斥；补单测 |

---

## 7. 非目标

- 不取消低置信确认产品能力  
- 不为写确认话术再开一轮 LLM  
- 不把确认文案写入 system 前缀
