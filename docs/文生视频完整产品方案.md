# 文生视频完整产品方案

> Second Person · 本地 ComfyUI + Wan 2.1 T2V 1.3B · 一次一条短视频 · 与现有 Agent 工具环 / SSE / `chat_images` 落盘模式 / Langfuse 对齐  
> 版本：2026-09-10（RTX 3070 8GB）  
> 对照文档：[`文生图完整产品方案.md`](./文生图完整产品方案.md)

## 产品一句话

对话模型（chat/agent）只负责「要不要拍、拍什么」；真正出视频由独立 **`video_gen` 槽位** 调 **本地 ComfyUI（Wan 2.1 T2V 1.3B / GGUF）**。成片立刻落本地 `chat_videos`，经 `tool_visual(type=generated_video)` 推前端，并写入本轮 `assistant.visuals`；Langfuse 记工具 span + 独立 generation，**不上报像素/帧本体**。

| 项 | 值 |
| --- | --- |
| 主路径 | 工具 `generate_video` |
| 出视频引擎 | **本地 ComfyUI + Wan 2.1 T2V 1.3B（GGUF 量化）** |
| 槽位 | `video_gen`（**无** chat/agent 回退） |
| 默认条数 | **1** |
| 单次上限 | **1**（V1 锁死；不做 batch） |
| 默认规格 | **480×832 竖屏** 或 **832×480 横屏**（V1 仅两档） |
| 默认时长 | **约 3s**（≈ 49 帧 @ 16fps，可配置夹紧） |
| 超时 | **600s**（本地视频远慢于文生图） |
| 文件名前缀 | `genv_` |
| 前端地址 | 只用本站 `/chat-videos/...` |

---

## 0. 为何选这条技术路线（3070 8GB）

文生视频比文生图吃显存与时间一个数量级。3070 **8GB** 上要同时满足「本地、对话内、可验收」，必须主动砍规格。

### 0.1 候选对比（本机约束）

| 方案 | 8GB 可行性 | 质量 | 耗时量级（3–5s 片） | ComfyUI 成熟度 | V1 建议 |
| --- | --- | --- | --- | --- | --- |
| **Wan 2.1 T2V 1.3B + GGUF** | ★★★★★（约 4–6GB） | 中上，运动尚可 | 约 2–6 min | 高 | **主路径** |
| LTX-Video / LTX-2 FP8+tiling | ★★★★（需强优化） | 中上，偏快 | 约 3–8 min | 高 | P1 可选 Adapter |
| Wan 2.2 5B / 14B GGUF | ★★★（offload 重） | 更好 | 更慢 | 高 | P2 质量升级 |
| CogVideoX-2B FP8 | ★★★ | 中 | 慢 | 中 | 备选 |
| HunyuanVideo / Mochi 全精 | ★（需极端量化） | 高但难稳 | 很长 | 中 | **不做 V1** |
| AnimateDiff (SD1.5) | ★★★★★ | 偏旧、闪烁多 | 较快 | 高 | 仅兜底，不进主路径 |

### 0.2 V1 锁定决策

1. **引擎复用文生图同一套 ComfyUI 进程**（`image_gen/comfyui`），另挂视频工作流；**不要**再起第二套便携包占磁盘。
2. **模型：Wan 2.1 T2V 1.3B 的 GGUF 量化版**（如 Q4/Q5），优先稳过炫。
3. **规格锁死短片：** 默认 ~3s、480p 档、一次一条；不做 720p / 10s+ / 批量。
4. **与文生图互斥占用 GPU：** V1 串行队列；生视频时不要并行 `generate_image`（同一 ComfyUI 队列也天然串行）。
5. **产品骨架对齐文生图：** 工具 → Adapter → 落盘 → `tool_visual` / `visuals`；不新增专用 HTTP。

### 0.3 用户预期（必须写进产品文案）

- 不是「秒出短视频 App」，而是「对话里要一条本地短片，等几分钟」。
- 常见耗时：**2–6 分钟**（冷启动、远控占显存、分辨率/帧数上浮会更久）。
- 画质与运镜受 1.3B + 480p 短片规格限制；适合概念演示、氛围片、简单主体运动，不适合复杂多人交互长镜头。

## 1. 角色拆分

| 角色 | 用哪个模型/槽 | 职责 | 禁止 |
| --- | --- | --- | --- |
| 对话 Agent | chat / agent（现有） | 理解意图；决定是否调用工具；把用户中文需求整理成清晰镜头描述；成片后写说明文案 | 自己编造视频 URL；把帧当文本输出；承诺「几秒内出片」 |
| 文生视频服务 | 新槽 `video_gen` → **ComfyUI Video Adapter** | 只接收结构化参数，调本地 ComfyUI 视频工作流，返回视频文件 | 参与多轮对话；读记忆；调其他工具 |
| 宿主（后端） | 无模型 | 校验参数、调 Adapter、落盘、发 SSE、写 DB、打点 Langfuse | 把 ComfyUI 临时路径 / `:8188/view` 直接暴露给前端 |
| 前端 | 无模型 | 展示 tool 进度（含「可能需要数分钟」）；渲染 `generated_video`；历史从 `visuals` 恢复 | 自行拼 `127.0.0.1:8188` |
| ComfyUI（外部进程） | Wan 1.3B + 视频工作流 | 真正扩散推理 | 不由 Second Person 内嵌进同一进程（V1） |

**槽位规则：** `video_gen` 不得 fallback 到 chat/agent。未配置或 ComfyUI 不可达时，工具返回明确错误，由 Agent 用文字告知——避免对话模型胡编视频。

**与 `image_gen` 关系：**

- 同属本地 ComfyUI，**不同槽位、不同工具、不同工作流、不同落盘目录**。
- Provider 可共用同一 `base_url`（8188），设置页分别绑定 `image_gen` / `video_gen`（可指向同一 Provider，或拆成两个逻辑 Provider 共用 URL）。
- V1：**同轮禁止**成功完成一次出图又一次出视频（显存与超时叠加不可控）；用户要「先画图再动起来」→ 多轮：先 `generate_image`，下一轮再 `generate_video`（P1 再做图生视频 I2V）。

**产品骨架：** Agent 工具主路径 → Adapter → `chat_videos` 落盘 → `tool_visual` / `visuals` 双通道；不新增专用 HTTP，仍走 `/api/chat/send` + 工具环。

## 2. 端到端时序（一次一条）

场景：用户说「生成一段橘猫在窗台晒太阳的短视频」。

| 步骤 | 谁 | 做什么 |
| --- | --- | --- |
| T0 | 前端 | `POST /api/chat/send`，body 与平时相同。**不新增**「生视频专用」HTTP；**不在前端指定工具**。 |
| T1 | 宿主 | 进入 `TurnRuntime`；SSE `turn_started` / `step_started`；组装 system + tools（含 `generate_video`）。 |
| T2 | 对话模型 | `source=agent_step`。判定需要出视频 → `tool_calls: generate_video`（条数固定按 1 处理）。 |
| T3 | SSE | `tool_executing`：`{tool_name:"generate_video", status:"running", …}`；前端文案：「正在本地生成短视频，可能需要几分钟，请稍候…」 |
| T4 | 工具执行 | 校验参数 → `snapshot_for("video_gen")` → **ComfyUI Video Adapter**：提交视频工作流 / 轮询队列 / 取视频 bytes → 写入 `data/chat_videos/genv_*.mp4`。 |
| T5 | SSE（双通道） | ① `tool_result`；② `tool_visual type=generated_video`。 |
| T6 | 回灌模型 | `role=tool` 短 JSON（`public_urls` / `filenames` / `latency_ms` / `duration_sec`），**不含** base64 / 帧序列。 |
| T7 | 对话模型 | 再一步写一句说明；`content_delta`。 |
| T8 | 落库终态 | `assistant.visuals` 含 `generated_video`；`turn_completed`。 |

**并行约定（V1）：**

- 禁止 batch / 禁止同一步多个 `generate_video` 并行
- 若模型误传 `n>1`：**夹紧为 1**，summary 说明「当前本地模式一次只生成 1 条」
- 用户要第二条：新一轮对话再调一次工具
- 同轮最多 **1** 次成功出视频
- 同轮若已成功出图：拒绝再出视频（或反过来），返回明确错误文案

**进度约定（强烈建议 P0 就做粗进度）：**

- Adapter 轮询 ComfyUI `/history` / queue 时，可周期性发 SSE `tool_progress`（若现有契约已有；没有则用 `tool_executing` 附带 `detail`）
- 前端至少展示：已等待秒数 +「本地 Wan，常见 2–6 分钟」

## 3. 来回链路对齐表

| 阶段 | 上游输入 | 下游输出 | 对齐键 |
| --- | --- | --- | --- |
| 用户 → 后端 | `ChatSendRequest.message` | conversations 用户行 + turn | `session_id` / `client_request_id` |
| Agent → 工具 | OpenAI `tool_call.function.arguments` | ToolExecutor 入参 dict | `call_id` |
| 工具 → ComfyUI | 规范化 `VideoGenRequest` | 本地工作流 prompt_id / 视频 bytes | `provider_id` + `model_id`（如 `wan21-t2v-1.3b-gguf`） |
| ComfyUI → 本地文件 | bytes | `genv_{12hex}.mp4` | `filename` |
| 工具 → 模型下一步 | `VideoGenResult` 短 JSON | `role=tool` content | `call_id` → `tool_call_id` |
| 工具 → 前端实时 | 同一 `VideoGenResult` | SSE `tool_result` + `tool_visual` | `turn_id` + `call_id` |
| 终态 → 历史 | `turn_visuals[]` | `conversations.visuals` | `message_id` |

**对齐原则：**

- 模型通道只传短元数据
- 像素/帧只走落盘 + `tool_visual` / `visuals`
- 禁止 data URI 进 tool role
- 禁止前端直连 ComfyUI（`127.0.0.1:8188` 等）
- Adapter 统一出口是 `VideoGenResult`；日后若接 LTX 等其它本地引擎，只换 Adapter，不改 SSE / 前端 / 落盘

## 4. 参数规则（3070 + Wan 1.3B）

### 产品默认（V1）

| 参数 | V1 默认 | 夹紧 / 备注 |
| --- | --- | --- |
| `n` | **1** | 上限 1 |
| `size` | **`480x832`**（竖） | 仅允许 `480x832` / `832x480`；其他映射回默认竖屏 |
| `duration_sec` | **3** | 允许 2–4；>4 夹紧为 4 并说明 |
| `fps` | **16** | 不开放给 Agent；写在工作流 |
| `frames` | 由 duration×fps 推导 | 约 32–64；服务端算，不让模型乱传 |
| steps | **20**（可配置） | 建议 16–24；不开放给 Agent |
| CFG / sampler | 工作流内置 | **不开放给 Agent（V1）** |
| 超时 | **600s** | 超时返回明确错误，不静默降规格重试 |
| 同轮 | 最多 **1** 条成功视频 | 与成功出图互斥 |

用户说「出多条 / 出 10 秒 / 出 1080p」：Agent 说明当前本地上限，需要则改参数到夹紧范围内再调，或引导新一轮。

### `config.yaml` 键

```yaml
video_gen_backend: comfyui
video_gen_default_n: 1
video_gen_max_n: 1
video_gen_turn_max_videos: 1
video_gen_default_size: "480x832"       # 或 832x480
video_gen_allowed_sizes:
  - "480x832"
  - "832x480"
video_gen_default_duration_sec: 3
video_gen_max_duration_sec: 4
video_gen_fps: 16
video_gen_timeout_sec: 600
video_gen_prompt_max_chars: 1500
video_gen_steps: 20
# 复用同一 ComfyUI；与 image_gen 可同 base_url
video_gen_comfyui_base_url: "http://127.0.0.1:8188"
video_gen_comfyui_root: "./image_gen/comfyui"
video_gen_comfyui_workflow: "./workflows/wan21_t2v_1_3b.json"
# 与文生图互斥（同轮）
video_gen_mutex_with_image_gen: true
```

### 工具参数 schema

```text
generate_video
required: [prompt]
properties:
  prompt: string          # 镜头描述；V1 建议英文（可由 Agent 或润色步骤产出）
  negative_prompt: string # 可选；缺省用工作流内置负面词
  size: string            # 仅 480x832 | 832x480；其他值服务端映射
  duration_sec: number    # 2–4；缺省 3；超出夹紧
  # n 仍可出现在 schema，但服务端强制夹紧为 1
  motion_hint: string     # slow|medium|dynamic → 并入 prompt 前缀（运镜/运动强度）
  style_hint: string      # cinematic|anime|realistic → 并入 prompt 前缀
```

### 显存与运行基线（写死到运维说明）

| 项 | 建议 |
| --- | --- |
| GPU | RTX 3070 8GB（空闲时约 7.9GB 可用） |
| 系统内存 | **建议 ≥32GB**（GGUF offload / text encoder 卸到 CPU 时需要） |
| 模型 | Wan 2.1 T2V 1.3B GGUF（Q4/Q5）+ 对应 VAE / text encoder |
| 默认 | 480p 档 · ~3s · 16fps · **每次 1 条** |
| ComfyUI | `--lowvram` 或社区 lowvram 工作流；生视频前清掉其它占显存进程 |
| 生视频前 | **务必**关闭向日葵 / ToDesk 等远控；尽量不要同时开浏览器硬解 4K |
| 不建议 V1 | 720p+、≥5s、batch≥2、同轮图+视频、14B 全精、Hunyuan 全精 |

## 5. 视频怎么保存

| 项 | 用户上传图（已有） | 模型生成图（已有） | 模型生成视频（本方案） |
| --- | --- | --- | --- |
| 目录 | `data/chat_images/` | `data/chat_images/` | **`data/chat_videos/`** |
| 文件名 | `img_{12hex}.{ext}` | `gen_{12hex}.png` | **`genv_{12hex}.mp4`**（V1 统一 H.264 MP4） |
| 消息字段 | `user.images` | `assistant.visuals[]` 含 `generated_image` | `assistant.visuals[]` 含 **`generated_video`** |
| 对外 URL | `/chat-images/{filename}` | 同左 | **`/chat-videos/{filename}`** |
| 静态挂载 | 已有 | 复用 | **新增** FastAPI StaticFiles 挂载 |
| 删除/备份 | 已有逻辑 | 扩展 visuals | 扩展 visuals 内 video filenames 清理 |

### 落盘契约

```text
bytes = comfyui.fetch_video(...)   # 或从 output 目录读入后立刻拷贝
fname = f"genv_{uuid4().hex[:12]}.mp4"
write(data_dir/chat_videos/fname, bytes)
# 不把 ComfyUI output 目录路径写进 DB / SSE
# 不把 http://127.0.0.1:8188/view?... 暴露给前端
# V1 统一转封装为 browser-friendly H.264 + yuv420p（若工作流输出 webm/其他，Adapter 内 ffmpeg 转一次）
```

**缩略图（P0.5 建议）：**

- 落盘同时抽首帧或中间帧 → `data/chat_videos/thumbs/genv_{id}.jpg`
- `VideoGenResult.poster_url` 可选；前端 `<video poster>` 用
- 不做则前端用视频首帧也行，但历史列表滚动会顿

**体积预期：** 3s@480p 通常数 MB 级；备份 `data/` 时注意视频比图大。

## 6. 前后端统一契约

### 6.1 `VideoGenResult`

```js
VideoGenResult = {
  type: "generated_video",
  filenames: string[],       // V1 长度恒为 1
  public_urls: string[],     // 长度恒为 1，如 /chat-videos/genv_xxx.mp4
  poster_url?: string,       // 可选缩略图
  n: 1,
  revised_prompt?: string,
  negative_prompt?: string,
  size: "480x832" | "832x480",
  duration_sec: number,
  fps: number,
  provider_id: string,
  model_id: string,          // 如 "wan21-t2v-1.3b-gguf"
  latency_ms?: number,
  backend: "comfyui",
  summary: string            // 如「已本地生成 1 条短视频（Wan 1.3B，约 3s，耗时 184s）」
}
```

### 6.2 SSE

现有事件集合尽量不变；前端文案与超时预期适配本地耗时（常见 **2–6 min**，冷启动更久）。

**白名单：** `generate_video` 必须进入 `tool_visual` 发射白名单。

**建议新增（若尚无）：**

- `tool_progress`：`{ tool_name, elapsed_ms, message }` — 长任务体验关键关键
- 或复用 `tool_executing` 的可更新字段，避免前端一直「假死感」

### 6.3 前端

- `generated_video` → 单路 `<video controls playsinline>`（V1 不做多视频网格）
- 时间线：生成中提示「本地 Wan 文生视频，可能需要几分钟」
- 失败时不发 `tool_visual`
- 历史恢复：从 `visuals` 读 `public_urls`，刷新后仍可播
- 移动端注意 `playsinline`；自动静音播放可选（V1 默认用户点播放，因本地片常无音轨）

### 6.4 设置页 / Provider

`TASK_SLOTS` 增加 `video_gen`：「文生视频模型（本地 ComfyUI）」。

| 字段 | 示例 |
| --- | --- |
| `provider_type` | `comfyui`（可与文生图同类型；靠槽位区分用途）或 `comfyui_video` |
| `base_url` | `http://127.0.0.1:8188` |
| `model_id` | Wan GGUF 文件名 / `wan21-t2v-1.3b-gguf` |
| `api_key` | 可空 |

`test-connection`：**GET ComfyUI `/system_stats` 或 `/queue`**，确认进程存活；可选再检查工作流 JSON / 模型文件是否存在（文件存在性检查在宿主侧做，不必 ComfyUI API）。

## 7. Prompt 规则

### A. 工具族规则 `base_rules_video_gen.md`

- 用户明确要求生成/拍/做一段视频/动画/短片时才调用
- **一次只生成 1 条**；用户要更多 → 说明后新一轮再调
- 默认约 **3 秒**；用户要更长 → 说明本地上限约 4 秒
- prompt 写**可见镜头**：主体、动作、场景、镜头运动（推拉摇移）、光线、风格；避免抽象口号
- **优先英文 prompt**；中文由 Agent 翻译或走润色
- 不要塞隐私信息；不要承诺商业级画质或配音（V1 默认可无音轨）
- 成功后一两句中文说明即可（时长、大致内容）；不伪造外链、不输出 base64
- ComfyUI 未启动 / 未配置 / OOM 时诚实说明
- 与出图互斥时：若用户同句又要图又要视频，先澄清做哪一个（V1 优先问清，或只执行一个）

### B. 润色（P0.5）

- `video_prompt_refine`：中文短句 → Wan 友好英文镜头描述 + 可选 negative_prompt
- 强调：**单一主体 + 单一明确动作**（多主体复杂交互在 1.3B 上容易糊）
- `source="video_prompt_refine"`；失败则回退 Agent 原始 prompt 仍出片

原因：本地小参数视频模型对提示词结构敏感，润色对「能动起来」影响大。

### C. 与文生图润色的差异

| | 文生图 | 文生视频 |
| --- | --- | --- |
| 重点 | 构图、材质、光影静态细节 | **动作连续性、镜头运动、时间顺序** |
| 忌讳 | 文字堆砌 | 多镜头分镜塞进一条 3s（应拆成多轮或多条） |
| 风格词 | photo/illustration… | cinematic / slow motion / handheld… |

## 8. Langfuse

挂在现有 `agent.turn` 下。只记 prompt / 条数 / 时长规格 / 耗时 / 文件名，不上报帧像素。

| 观测 | name | 记录内容 |
| --- | --- | --- |
| span | `tool_execute` | tool 名、prompt preview、ok、filenames、n、latency、duration_sec |
| generation | `llm.video_gen` | prompt、size、frames/fps、steps、model_id、backend=`comfyui`、latency_ms、filenames；**无像素**；`video_count=1` |
| generation（P0.5） | `llm.video_prompt_refine` | 短句 → 润色结果 |

## 9. 错误与边界

| 情况 | 工具返回 | 用户感知 |
| --- | --- | --- |
| 未配置 `video_gen` | `ok:false` | 引导去设置页 |
| ComfyUI 未启动 / 连接失败 | `ok:false`「本地生视频服务未启动」 | 提示先打开 ComfyUI |
| 显存不足 / ComfyUI 报 OOM | `ok:false` | 建议关掉远控与其它占显存程序后重试；**不要**静默降分辨率乱试（可提示「可改为更短 duration」作为人工建议） |
| 超时（>600s） | `ok:false` | 可重试；检查是否卡在队列 / 是否在卸模型 |
| `n>1` / `duration` 过大 / 非法 size | 夹紧或拒绝并说明 | 「当前一次 1 条、最长约 4 秒、仅 480p 两档」 |
| 同轮已出图又要出视频 | `ok:false` | 「本轮已生成图片，请新开一轮再生成视频」 |
| 取消 turn | 尽量取消 ComfyUI 队列任务（若 API 支持）；已落盘保留 | 与现有取消一致 |
| 输出非 MP4 | Adapter 转码失败 | 明确错误；保留原始临时文件便于排障（不进前端） |
| 远程桌面占显存 | 不自动处理 | 文档/错误文案提示：生视频前尽量关闭远控 |
| 磁盘空间不足 | `ok:false` | 提示清理 `chat_videos` / ComfyUI `output/` |

## 决策摘要

1. **引擎：本地 ComfyUI + Wan 2.1 T2V 1.3B（GGUF）** — 3070 8GB 最稳的主路径  
2. **条数：严格一次一条；时长约 3s；仅 480p 两档**  
3. **目录：复用 `image_gen/comfyui/`；成片进 `data/chat_videos/`**  
4. **产品骨架：** 工具 → Adapter → 落盘 → `tool_visual` → `visuals`（对齐文生图）  
5. **必须补强：** 600s 超时、进度/耗时文案、英文镜头润色、OOM/未启动/与出图互斥错误文案  
6. **扩展：** LTX / 更大 Wan / I2V 等其它本地引擎只换 Adapter，不进 V1 主路径  
7. **诚实预期：** 本地短片概念验证；受 3070 8GB 规格约束，不以长片/高清为目标

## 附录 A · 推荐工作流占位说明

仓库内 `workflows/wan21_t2v_1_3b.json` 落地时应固定：

- 输入槽：`prompt` / `negative_prompt` / `width` / `height` / `num_frames`（或 length）
- 输出：单文件视频（优先 mp4）；若节点只出帧序列，由 Adapter 调 ffmpeg 合成
- 采样步数、CFG、scheduler：写死在模板，宿主只替换上述输入
- 文件名/Save 节点：指向 ComfyUI `output/` 临时名；宿主拷贝后可删

## 附录 B · 为何不把视频塞进 `chat_images`

- MIME、静态缓存、清理策略、体积与备份策略均不同  
- URL 前缀分离后，前端可按路径类型选 `<img>` / `<video>`，契约更清晰  
- 与现有 `img_` / `gen_` 命名空间不冲突（视频用 `genv_`）
