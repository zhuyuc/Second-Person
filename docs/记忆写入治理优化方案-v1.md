# Second Person 记忆写入治理优化方案

> 落地状态：本方案的候选池、评分、敏感信息门禁、证据合并和状态机已实现。当前生产实现以 `memory/write_gate.py`、`migrations/041_memory_write_governance_v2.sql`、`agent/system_agents.py` 和 `app/routes/memory.py` 为准；本文中 `review_candidates`、旧版直接回顾写入等描述属于迁移前背景。

## 1. 目标与结论

当前系统已经具备主动记忆、半主动确认、被动候选、文档导入预览、合并去重和生命周期治理。事实提取与长期写入已经由 `MemoryWriteGate` 分层：候选先进入 `memory_write_candidates`，经过敏感信息检查、评分、证据合并和用户确认/跨会话证据门槛后，才允许交给 `Distiller` 写入 L3。

本方案的核心结论是：

> “事实抽取”不等于“记忆写入”。所有非用户明确指令的内容，先进入短期候选池；只有经过硬门禁、价值评分和必要确认，才允许进入长期记忆。不能判定为长期价值的内容留在会话日志或候选池，并按 TTL 自动清理。

目标不是让系统少记，而是让长期记忆更可信、更少打扰、更容易被检索命中。主动记忆指令仍然保持低摩擦，但也必须经过格式校验、去重和敏感信息安全检查。

## 2. 调研范围与可借鉴结论

### 2.1 本项目现状

调研文件：

- `agent/core.py` / `agent/turn_runtime.py`：宿主执行主动记忆工具和事件化回填。
- `agent/system_agents.py`：系统 Agent 提取候选并调用写入治理流程。
- `memory/distiller.py`：归属、向量/BM25 去重、same/evolved/contradicts/related 关系判定和 FileWriter 写入。
- `memory/retriever.py`：混合检索、个人/知识问题权重、低置信和过期记忆过滤、检索诊断。
- `memory/lifecycle.py`：置信度、stale、review_due、引用计数、用户负反馈和治理队列。
- `migrations/009_memory_governance.sql`、`migrations/039_memory_experience.sql`：已有候选、证据、版本、反馈、检索轨迹和治理表。

现有优势：Markdown 是主副本、FileWriter 是统一写入者、SQLite 是派生索引；记忆已有 `verification_state`、`freshness_state`、`review_after`、`retrieval_negative_count` 和 `memory_governance_items` 等治理基础。

关键缺口：

1. 被动候选只由句式触发，没有“稳定性、可复用性、用户意图、敏感性、时效性”门禁。
2. 迁移前的 `review_candidates` 只有一条消息引用和优先级，无法表达候选的证据数量、评分、拒绝原因、过期时间和确认状态；当前已由 `memory_write_candidates` 补齐。
3. 被动回顾消费后会直接进入 `Distiller`，缺少“候选 -> 提炼待审 -> 长期记忆”的第二道代码门禁。
4. `session_fact` 虽然不进 L3，但候选上下文、任务计划和临时偏好仍可能被事实句式误捕获。
5. 检索负反馈已经记录，但尚未反向降低相似候选的写入资格，也没有形成“重复无关记忆自动抑制”规则。

### 2.2 Codex / OpenAI 官方文档

本次使用 Codex 对本地代码和 DeepSeek harness 做了结构化检查，并参考了 OpenAI Docs 的上下文管理说明。官方建议将长期运行上下文视为“可回放状态”和“压缩后的工作上下文”两个不同层次：Responses API 的 compaction 用于继续任务，输出是不透明的、不可依赖内部结构的压缩项；应在重要里程碑后压缩，而不是每轮压缩，并保持恢复时的提示语义一致。[OpenAI Docs：GPT-5.2 Model Guidance](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.2)

对本项目的启示：会话上下文摘要、工具结果裁剪和长期记忆必须分层，不能把上下文压缩结果当成用户事实直接写入记忆宫殿；长期记忆必须有可解释的来源和独立生命周期。

### 2.3 DeepSeek harness 本地项目

调研目录：`D:\AI沙盒\DeepSeek harness\deepseek-harness`。

重点借鉴：

- `packages/session` 使用 append-only `SessionEvent` 作为会话唯一事实源，派生视图和投影缓存不能取代事件日志。
- session persistence 由统一 coordinator 串行写入，写入完成才返回；崩溃时保留已经持久化的事件，仅补充可回放的关闭事件，不静默篡改历史。
- `packages/compaction/compaction-basic` 将“模型可见内容”与“持久化事件”绑定，先做无模型工具结果裁剪，再按 token 压力选择可压缩区间；压缩结果是表面替换，不是把每段内容永久记成新事实。
- compaction 支持 pressure 和 context-overflow 两类触发，允许重试，但只有持久化表面真正前进时才重试，避免无效循环。
- `session-projection-cache` 只保存可重建的派生投影，不把投影当作原始会话事实。

对本项目的直接借鉴：

1. L2 会话记录、L1 压缩摘要和 L3 长期记忆必须有不同数据类型和不同写入入口。
2. 所有影响模型输入的记忆筛选结果要可追踪，至少记录候选、选中、拒绝和原因。
3. 先做零 LLM 的硬门禁和裁剪，再调用 LLM 进行少量高价值判断。
4. 记忆写入要可重试、幂等、可恢复，不能因异步回顾重复生成多条副本。

## 3. 记忆分层与写入边界

| 层级 | 存储 | 允许保存的内容 | 默认保留 | 是否进入长期检索 |
| --- | --- | --- | --- | --- |
| L0 当前请求 | 请求上下文、工具中间结果 | 本轮任务所需材料、附件、临时变量 | 请求结束 | 否 |
| L1 工作记忆 | 当前会话内存/压缩摘要 | 当前目标、约束、已做决定、未决问题 | 会话级 | 仅当前会话 |
| L2 会话记忆 | `conversations`、session 摘要 | 可回放的会话事实和 handoff 摘要 | 永久保留原文，摘要可重建 | 默认否 |
| L3 长期记忆 | `data/memories/*.md` + SQLite/向量 | 稳定、可复用、用户相关且有证据的事实/偏好/决定 | 进入生命周期治理 | 是 |
| 候选池 | `memory_write_candidates` | 尚未达到 L3 门槛的候选及证据 | 7~30 天 TTL | 否 |

以下内容默认禁止进入 L3：

- 单轮任务过程、临时草稿、一次性提醒、未确认的计划和假设。
- 普通知识、网页正文、附件全文；知识应进入知识库或 raw document，不伪装成个人记忆。
- 只描述当前情绪、当前环境或当前对话状态的内容，除非用户明确要求保存为长期偏好。
- “可能、也许、我猜、暂时、这次、今天、先这样”等明显时效或不确定表达。
- 密码、API key、验证码、支付信息、精确住址、身份证件等高敏感信息。用户明确要求保存时也只保存经过脱敏的提示，不保存秘密原文。
- 与已有记忆语义重复但没有新证据、新版本或冲突信息的表达。

## 4. 新的写入决策模型

### 4.1 四类写入通道

| 通道 | 触发 | 默认动作 | 用户确认 |
| --- | --- | --- | --- |
| `explicit` | 用户明确说“记住/保存/以后都按这个” | 直接进入写入校验；通过后写入 | 不需要再次确认，但展示已保存结果 |
| `confirmable` | 用户表达稳定偏好、决定或个人事实，但未明确保存 | 进入候选池，累计证据 | 达到阈值后自然确认或在记忆中心确认 |
| `session_only` | 任务上下文、临时计划、当前状态、一次性知识 | 只留 L1/L2 | 不询问 |
| `knowledge` | 文档、网页、附件、外部资料 | 进入 raw_docs/知识库；可生成有来源的知识条目 | 按导入模式决定 |

通道由规则先判定，LLM 只负责结构化候选和边界不确定时的分类，不允许 LLM 直接绕过代码门禁写 L3。

### 4.2 候选评分

对非 `explicit` 内容计算 `memory_value_score`，范围 0~100：

```text
score = 25 * stability
      + 25 * reuse
      + 20 * user_specificity
      + 15 * explicitness
      + 15 * evidence_quality
      - 25 * temporariness
      - 30 * sensitivity_risk
      - 20 * duplicate_penalty
```

每项为 0~1 的规则分，不直接暴露给用户。建议门槛：

| 分数/条件 | 动作 |
| --- | --- |
| `score < 45` 或命中禁止项 | 丢弃候选，保留拒绝原因和指标 |
| `45 <= score < 70` | 候选池，TTL 7 天，不主动询问 |
| `70 <= score < 85` | 候选池，要求第二次独立证据或一次用户确认 |
| `score >= 85` 且无风险项 | 可进入待写入队列；仍需去重和安全扫描 |
| `explicit` | 跳过分数门槛，但不得跳过敏感信息、安全、格式和去重检查 |

稳定性证据按“跨会话、跨时间、非复制表达”计算；同一会话内重复三次不算三条独立证据。

### 4.3 证据与确认规则

- 个人事实/偏好：至少 2 次跨会话证据，或 1 次明确确认。
- 长期决定/约束：1 次明确确认即可；没有确认时 TTL 14 天。
- 推断内容：只能保存为 `confidence=low`，默认不参与普通检索；必须有明确回忆意图才可检索。
- 用户说“不要记住/忘掉”：立即撤销相关候选；若已存在 L3，执行归档或删除流程并记录审计。
- 用户纠正已有记忆：走 `evolved` 或 `contradicts`，保留版本和证据，不覆盖原文而丢失历史。

## 5. 端到端数据流

```text
用户消息/工具输出
        |
        v
规则预过滤（意图、临时词、敏感信息、附件/知识来源）
        |
        +--> session_only ----> L1/L2，会话结束后不进 L3
        |
        +--> knowledge -------> raw_docs/知识库，不走个人记忆入口
        |
        v
候选提取（LLM 结构化，不写盘）
        |
        v
候选评分 + 证据去重 + 负反馈抑制 + TTL
        |
        +--> reject ----------> candidate audit，结束
        |
        +--> pending ----------> memory_write_candidates
        |                           |
        |                           +--> 第二证据/用户确认
        |                           |
        v                           v
安全扫描 -> 相似/冲突判定 -> FileWriter 单写队列 -> L3 md + SQLite/向量
                                           |
                                           v
                              引用反馈 / stale / review / archive
```

### 5.1 写入前强制门禁

`Distiller._write_memory()` 前新增 `MemoryWriteGate`，任何来源都必须经过：

1. `source_type` 和 attribution 白名单校验。
2. `session_fact`、`temporary`、`knowledge_raw` 等非 L3 类型拒绝。
3. 敏感信息扫描与脱敏；命中高风险直接拒绝。
4. 候选评分和证据数量校验；非 explicit 未达门槛直接返回 `pending`。
5. 用户拒绝保护期和相似候选负反馈抑制。
6. 去重/演变/矛盾关系判定。
7. FileWriter 幂等提交，提交成功后再更新候选状态。

写入状态必须是可恢复状态机：`pending -> approved -> writing -> written`，失败为 `failed`，过期为 `expired`，拒绝为 `rejected`。禁止先删候选再写记忆。

## 8. 检索体验闭环

### 8.1 召回门禁

检索排序仍使用向量 + FTS5 + RRF，但增加以下硬条件：

- `write_channel=knowledge` 的条目只在知识型问题或明确知识库检索时参与。
- `write_channel=confirmable` 且未确认、`verification_state=inferred` 的条目默认不注入，只在明确“你还记得/我之前说过”时提供并标注不确定。
- `freshness_state in (expired, review_due)` 默认不注入；用户明确回忆时可以展示，但不作为当前事实陈述。
- `retrieval_negative_count >= 2` 的条目从普通召回候选降为治理候选，除非用户明确点名或给出回忆意图。
- 重要记忆加权只能在通过相关性和新鲜度门禁后执行，不能让“重要”复活无关条目。

### 8.2 负反馈反哺写入

当用户将某条记忆标记为无关时：

1. 当前记忆 `retrieval_negative_count + 1`。
2. 以同一 fingerprint 的候选在 30 天内增加 `duplicate_penalty`。
3. 同一查询类型下连续两次无关，创建 `memory_governance_items(retrieval_irrelevant)`。
4. 治理任务优先合并、降权、stale 或归档，不自动删除用户明确保存的记忆。

这样可以把“误检索”变成“减少未来误写入和误召回”的反馈闭环。

## 9. 用户体验

- 用户说“记住”时：回复“已保存：标题”，同时提供撤销入口；不要求重复确认。
- 系统发现可能有长期价值但证据不足时：不打断当前回答，不主动追问；只在记忆中心显示“待确认候选”。
- 候选达到第二证据时：可在自然对话中最多询问一条，询问必须说明“是否以后按此作为你的偏好/事实”，用户拒绝后进入保护期。
- 用户说“忘掉/不要记住”时：候选立即撤销，L3 记忆进入归档/删除确认流程。
- 记忆中心新增“待确认候选”视图，显示来源、摘要、评分、证据数、过期时间和拒绝原因；不展示内部模型推理文本。

## 11. 测试与验收

### 11.1 单元测试

- 明确“记住”写入；空标题、重复、敏感信息被拒绝。
- “我今天准备……”、“这次先……”、“附件里……”进入 session-only/knowledge，不进入 L3。
- 同一事实同会话重复表达不会增加独立证据数。
- 跨会话第二证据升级候选；拒绝进入保护期；TTL 到期变为 expired。
- 写入失败保留 candidate=failed，可重试且不会生成重复 md。
- `Distiller` 关系判定仍正确处理 same/evolved/contradicts/related。
- 检索负反馈达到阈值后抑制相似候选和普通召回。

### 11.2 回归与契约

- 更新 `tests/test_prompt_registry.py` 对 prompt、调用点和登记表的校验。
- 新增迁移链测试、候选状态机测试、API envelope/SSE 契约测试。
- 保持 `tests/test_retriever_gates.py`、`tests/test_memory_experience.py`、`tests/test_profile_review.py` 现有语义，并补充 session-only/knowledge/explicit 三类样例。
- 运行后端 pytest、前端既有构建与静态资源一致性检查；不手工修改 `app/static`。

### 11.3 关键指标

上线前建立基线，灰度后观察：

- L3 新增量：目标下降 40%~70%，但显式保存成功率不下降。
- 普通对话无关召回率：目标下降 50% 以上。
- 记忆引用后用户正向反馈率：目标提升 20% 以上。
- 候选自动过期率：观察是否高于 60%；过高说明提取仍然过宽。
- 显式记忆撤销率、敏感信息拦截率、写入失败重试成功率。

指标只用于校准阈值，不把“写入数量”作为成功标准。

## 12. 实施顺序

### Phase 1：硬门禁与候选状态机（已落地）

已新增迁移、`MemoryWriteGate`、候选表和显式/非显式通道；session-only、知识原文、敏感信息和低分候选会被门禁阻断。

### Phase 2：证据累积与用户确认（已落地）

当前直接使用 `memory_write_candidates`，支持跨会话证据、TTL、拒绝保护和记忆中心 API/UI；后台只消费达到门槛的候选。

### Phase 3：检索负反馈闭环（已接入）

已接入 `memory_feedback`、`retrieval_events` 和 `memory_governance_items`，门禁会读取检索负反馈并抑制自动写入。

### Phase 4：阈值校准与灰度

用现有 Langfuse/开发者 trace 记录候选分数、门禁、写入结果和引用反馈；以真实样本校准阈值，保留配置开关和回滚路径。

## 13. 不做的事情

- 不把所有对话自动摘要成长期记忆。
- 不把 DeepSeek harness 的 compaction 摘要直接写入 L3。
- 不为每个领域生成独立能力或独立记忆目录；领域只是索引和检索维度。
- 不删除会话原文；L2 仍是可回放事实源，L3 是经过治理的派生长期记忆。
- 不用更低阈值换取“记忆丰富度”，质量优先于写入数量。

## 14. 最终验收标准

当且仅当以下条件全部满足，认为本方案完成：

1. 用户未明确要求保存时，普通聊天、任务过程、临时计划和知识正文不会直接进入 L3。
2. 每条非显式 L3 记忆都能追溯到候选、评分、证据和写入原因。
3. 写入失败可恢复，重复重试不会产生重复记忆。
4. 用户拒绝、忘记和无关反馈会影响后续候选和召回。
5. L1/L2 压缩与 L3 长期记忆完全分离，任何上下文摘要都不能绕过写入门禁。
6. 现有 FileWriter、SQLite 派生索引、Prompt 注册表、API envelope、SSE 和目录规范全部保持一致。
