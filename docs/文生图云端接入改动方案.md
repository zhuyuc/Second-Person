# 文生图接入云端模型改动方案

> 状态：改动方案（未改码）  
> 对照：文生视频云端路径（可灵 `KlingVideoAdapter` + `VideoProfile` + 设置引导）  
> 结论：**可以接入，且 OpenAI 兼容云端图路径已基本可用**；当前主问题是「产品化不足、协议过宽、能力表缺失」，不是从零造云端图。

---

## 1. 现状判断

### 1.1 一句话

| 能力 | 现状 |
|------|------|
| 本地文生图 | ComfyUI + SDXL，产品文档主叙事 |
| 云端文生图 | **代码已通**：`OpenAIImageAdapter` → `POST /images/generations` |
| 云端文生视频 | **产品更完整**：可灵专用 Adapter + Profile + Auth + 异步轮询 + 设置页默认值 |
| 差距 | 图侧缺「视频同级」的可发现性、能力表、协议收窄、多供应商 |

### 1.2 已具备（不必重写）

```
generate_image
  → providers.snapshot_for("image_gen")
  → get_image_adapter(snap)
       comfyui     → ComfyUIAdapter
       cloud_http  → OpenAIImageAdapter   ← 已存在
  → 落盘 data/chat_images/gen_*.png
  → tool_visual(type=generated_image)
```

- 槽位文案已写「可绑云端图片模型（OpenAI 兼容）或本地 ComfyUI」  
- 工具内已区分本地/云端 `size`；润色仅本地 GPU  
- `remote_jobs` kind=`cloud_image`（下载阶段可 resume）  
- 单测：`test_image_factory_picks_cloud_adapter` 等  
- 设置页已有图片模态、¥/张计价

### 1.3 相对文生视频的缺口

| # | 缺口 | 视频侧已有 | 图侧影响 |
|---|------|------------|----------|
| 1 | 产品文档仍写死「仅本地 SDXL」 | 代码+设置已宣传云端 | 用户不知道能配云端图 |
| 2 | 设置页无图片云端默认 URL/模型/Key 提示 | `isVideoCloud` → kling 默认 | 易填错 |
| 3 | 无 `ImageProfile` | `VideoProfile` 本地/云端隔离 | size/timeout/refine 散落在 tool |
| 4 | 无共享 `execute_image_gen` | `execute_video_gen` | 难复用工坊/续跟 |
| 5 | `anthropic` 可绑 image，但 Adapter 只认 Images API | 视频云端专走可灵 | 配置能过、运行必挂 |
| 6 | probe 只 `GET /models` | 可灵有业务探测 | 「测试连接」假绿 |
| 7 | 仅 OpenAI Images 形态 | 可灵专用协议 | Flux/Stability/国内生图未接 |
| 8 | `style_hint` 仅本地前缀 | 云端参数映射清晰 | Agent 参数对云端无效 |
| 9 | 异步长任务图供应商 | submit→poll→download | 同步 POST 够用；长任务不行 |

## 2. 目标形态（对齐视频骨架）

```
modality=image Provider
  → snapshot_for("image_gen")
  → image_profile_for(snap, config)     # 新增：本地/云端参数隔离
  → get_image_adapter
       comfyui           → ComfyUIAdapter
       openai_compatible → OpenAIImageAdapter（增强）
       （可选）vendor_x  → 专用 Adapter
  → execute_image_gen（新增共享执行体）
  → 落盘 + Langfuse + ¥/张计费
```

**产品一句话（更新后）：**  
对话模型只负责「要不要画、画什么」；出图由 `image_gen` 槽位调用 **本地 ComfyUI（SDXL）或云端 OpenAI 兼容图片 API**（及后续扩展供应商）。

## 3. 改动范围

### Phase A — 让现有云端图「可发现、可配」（P0，低风险）

| 项 | 改动 | 参考视频 |
|----|------|----------|
| A1 文档 | 更新 `docs/文生图完整产品方案.md`、`image_gen/README.md`：双引擎表 | 视频方案结构 |
| A2 设置引导 | `isImageCloud`：默认 `base_url`（如 `https://api.openai.com/v1`）、占位模型（`dall-e-3` / `gpt-image-1`）、API Key 提示 | `isVideoCloud` |
| A3 协议收窄 | image 云端仅允许 `openai_compatible` + `custom`；绑 `anthropic` 时设置页/保存校验拒绝并提示 | 避免假配置 |
| A4 Agent 文案 | `base_rules_image_gen.md`、能力 hint：写明本地/云端差异（无 steps、无本地润色） | `base_rules_video_gen.md` |
| A5 配置说明 | `PARAM_SCHEMA`：标注 `image_gen_steps` / `image_gen_refine_enabled` **仅本地生效** | 视频 timeout 共用说明 |

**验收：** 设置页新建「OpenAI 兼容」图片 Provider → 绑到 `image_gen` → 对话出图成功；未配 Key 时错误明确。

### Phase B — 能力表 + 执行体对齐视频（P1）

| 项 | 改动 |
|----|------|
| B1 | 新增 `infrastructure/image_gen/profiles.py`：`LOCAL_PROFILE` / `CLOUD_PROFILE`（sizes、timeout、refine on/off、engine） |
| B2 | `image_profile_for(snap, config)`；`image_capability_hint` 改为基于 Profile |
| B3 | 抽 `infrastructure/image_gen/execute.py`（`execute_image_gen`）；`builtin.generate_image` 变薄 |
| B4 | 云端忽略 `steps`/`style_hint`，或映射到供应商字段（如 quality）；本地保持现状 |
| B5 | probe：可选轻量 images dry-run，或文案标明「/models 仅连通性」 |

**验收：** 切换本地/云端 Provider 后，Agent 看到的能力摘要与真实夹紧一致；单测覆盖 profile 选择。

### Phase C — 扩展供应商（P2，按需）

| 项 | 说明 |
|----|------|
| C1 | 新 Adapter 接口稳定化：`probe` / `generate` /（可选）`resume` |
| C2 | factory 按 `model_id` 或 host 路由专用 Adapter（照抄可灵，不硬塞进 OpenAI body） |
| C3 | 异步云端图：复用 `remote_jobs` submit/poll/resume（`kling_video` 模式） |
| C4 | 候选供应商（择一优先）：OpenAI 官方增强（gpt-image 参数）、SiliconFlow/通义等 OpenAI 兼容、Stability、可灵生图 |

**验收：** 至少再接入 1 家非「裸 OpenAI Images」供应商，或完成 gpt-image 参数建模。

## 4. 关键设计细节

### 4.1 `ImageProfile`（建议字段）

```python
@dataclass(frozen=True)
class ImageProfile:
    engine: str              # comfyui | openai_images | ...
    local_gpu: bool
    allowed_sizes: tuple[str, ...]
    default_size: str
    timeout_sec: float
    refine: str              # local_zh | off
    supports_style_hint: bool
    supports_steps: bool
```

| | LOCAL | CLOUD（OpenAI Images） |
|--|-------|-------------------------|
| sizes | 1024 系（现有） | 1024x1024 / 1024x1792 / 1792x1024 |
| refine | 可开 | **off** |
| steps | 可用 | **忽略** |
| timeout | `image_gen_timeout_sec` | 同配置或略短读超时 |

### 4.2 设置页引导（对齐视频）

```text
isImageCloud = modality===image && !comfyui

默认建议：
  base_url: https://api.openai.com/v1
  model_id: dall-e-3   # 或 gpt-image-1
  api_key: 必填提示
计价：¥/张（已有）
```

国内 OpenAI 兼容网关：用户改 `base_url` + `model_id` 即可，**不必改代码**（Phase A 已覆盖）。

### 4.3 与本地互斥

- GPU 互斥：仅当 `image_gen`/`video_gen` 绑 **本地 ComfyUI** 时生效（现状合理）  
- 云端图 + 本地视频：可并行（无共享 GPU）；产品可不强制互斥  
- 同轮「一张图」规则保持

### 4.4 明确不做（本方案边界）

- 不把 chat/vision 槽位当出图引擎  
- 不把 Anthropic Messages 协议伪装成生图  
- Phase A/B 不强制上异步多供应商  
- 不上报像素到 Langfuse（与现网一致）

## 7. 风险

| 风险 | 对策 |
|------|------|
| 用户把对话模型 URL 填进 image_gen | 设置引导 + probe 失败文案指向 `/images/generations` |
| 兼容网关半实现 Images API | 文档列出必测项：generations + b64/url |
| gpt-image-1 参数差异 | Phase C 建模 quality/output；A 阶段用 dall-e-3 作默认 |
| 本地文档过时继续误导 | A1 必须先改产品方案标题与「一句话」 |

---

## 8. 决策摘要

| 问题 | 答案 |
|------|------|
| 能否接云端文生图？ | **能；最小路径已存在** |
| 要不要照抄可灵？ | **抄骨架（Profile/设置/执行体），不抄可灵协议** |
| 当前本地用户怎么切云端？ | 设置页新增 OpenAI 兼容图片 Provider → 绑 `image_gen` → 填 Key |
| 优先改什么？ | **可发现性（A）> 能力表（B）> 多供应商（C）** |
