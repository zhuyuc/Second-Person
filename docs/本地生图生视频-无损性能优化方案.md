# 本地生图 / 生视频 · 无损性能优化方案（完整版）

> Second Person · 在 **不改变输出质量** 的前提下，提升本地 ComfyUI（SDXL + Wan 2.1 T2V 1.3B）的运行效率与显存稳定性  
> 版本：2026-10-08（目标硬件：RTX 3070 8GB 级） · **已落地实现**  
> 对照文档：[`文生图完整产品方案.md`](./文生图完整产品方案.md)、[`文生视频完整产品方案.md`](./文生视频完整产品方案.md)  
> 安装：`image_gen/setup_lossless_accel.ps1` · 验收：`scripts/verify_local_gen_quality.py`

---

## 1. 产品一句话

本地出图 / 出视频仍走现有 **`generate_image` / `generate_video` → ComfyUI Adapter → 同一 `:8188` 进程**；优化只发生在 **Attention 算子** 与 **显存调度**，不更换模型、不减少采样步数、不做权重量化、不做跳步缓存。用户感知应是「更快或更少 OOM」，而不是「画质变了」。

| 项 | 值 |
| --- | --- |
| 优化档位 | **无损档（本方案唯一默认档）** |
| 引擎 | 现有 `image_gen/comfyui`（不新起第二套 ComfyUI / 不新端口） |
| 图模型 | 继续 `sd_xl_base_1.0.safetensors`（fp16/safetensors） |
| 视频模型 | 继续 `wan2.1_t2v_1.3B_fp16.safetensors` + 现有 VAE / UMT5 |
| 规格 | 维持现网默认：图 `1024x1024`；视频 480p 档 · ~3s · 16fps · n=1 |
| 对话 / SSE / 落盘 / Langfuse | **不变** |
| 有损手段（量化 / MagCache / Lightning 等） | **本方案禁止**；若未来需要另开「有损加速档」文档 |

## 2. 硬约束：什么叫「不影响质量」

### 2.1 定义

在固定验收用例下，开启优化后须同时满足：

1. **生成参数不变**：`steps` / `cfg` / `sampler` / `scheduler` / `size` / `duration` / `fps` / `frames` 与优化前配置一致。  
2. **权重不变**：主路径仍为 fp16（或当前已在用的非量化 safetensors），**不以 GGUF/INT4 等作为默认**。  
3. **计算路径不跳步**：工作流不得包含 MagCache / TeaCache 等「跳过 denoising step」节点。  
4. **同 seed 可验收**：同一 prompt + seed + 参数，输出与基线在观感上一致；量化指标建议：
   - 图：SSIM ≥ **0.99**（或团队约定更高），允许浮点级像素差；
   - 视频：抽取固定关键帧做同样对比；不允许「运动明显变弱 / 明显发糊」类观感回归。  
5. **不得**为过验收而静默降低分辨率、时长或步数。

> 说明：SageAttention 属于高质量近似 Attention，属业界常认定的「近似无损」。若团队要求「同 seed 文件哈希完全一致」，可将 Sage 设为可开关，并以 SSIM 为主验收，不以字节哈希卡死。

### 2.2 禁止清单（本方案一律不做）

| 禁止项 | 原因 |
| --- | --- |
| GGUF / GPTQ / AWQ / INT8 权重量化作主路径 | 改变权重数值，质量下降 |
| MagCache / TeaCache / 其它 step-skipping cache | 少算步，运动与细节会漂 |
| SDXL-Lightning / LCM / Hyper-SD / 蒸馏少步模型 | 换模型或少步，画质与风格变 |
| 为「优化」降低默认分辨率、帧数、steps、CFG | 规格本身即质量上限 |
| 激进 Tiled KSampler（会引入接缝或可见差异） | 结果可能偏离基线 |
| 另起 vLLM / 独立推理服务 / 第二套 ComfyUI | 偏离现有架构，也非本问题域 |
| 同轮并行出图又出视频 | 已有产品规则；并行会争显存导致失败或被迫降规格 |

### 2.3 允许清单（质量中性）

| 允许项 | 作用 | 质量影响 |
| --- | --- | --- |
| SageAttention（或等价高质量 Attention 后端） | 加速 Attention 算子 | 近似无损 |
| ComfyUI `--lowvram` / `--reserve-vram` | 分层装载，降峰值显存 | 不改数学结果 |
| Wan BlockSwap（**最小必要**块数） | 层在 CPU/GPU 间交换 | 不改数学结果 |
| UMT5 / T5 文本编码器卸 CPU | 降视频峰值显存 | 不改数学结果 |
| Block prefetch（如 `prefetch_blocks=1`） | 搬运与计算重叠 | 不改数学结果 |
| 进程卫生：关远控、串行队列、权重常驻少切换 | 减少抢占与冷启动 | 不改数学结果 |
| 同 seed 回归脚本 / 显存探针提示 | 工程保障 | 不改生成 |

## 3. 背景与问题

### 3.1 现状

| 能力 | 路径 | 典型痛点 |
| --- | --- | --- |
| 文生图 | `image_gen` → `ComfyUIAdapter` → `workflows/sdxl_txt2img.json` | 8GB 上与视频争显存；采样偏慢 |
| 文生视频 | `video_gen` → `ComfyUIVideoAdapter` → `workflows/wan21_t2v_1_3b.json` | 耗时长、峰值高、易 OOM |
| 引擎 | 共用 `image_gen/comfyui`，lazy `ensure_comfyui` | 已满足「单进程」前提 |

产品规格层已做的容量控制（视频 480p / ~3s / n=1 / 图视频互斥）**保留**，本方案不再靠继续砍规格换性能。

### 3.2 优化从哪几面下手（且不伤质量）

```text
算子效率     → SageAttention          → 同一步算得更快
驻留策略     → lowvram / BlockSwap / T5→CPU → 峰值显存更低（可能略慢）
运行卫生     → 串行、常驻、清占用人   → 少失败、少冷启动
工程接入     → setup + 启动参数 + 工作流节点 → 用户无感，仍走对话工具
```

**明确不做的加速面**：权重量化、跳步缓存、蒸馏少步——这些都会动质量。

### 3.3 预期收益（在质量不变前提下）

| 维度 | 预期 | 备注 |
| --- | --- | --- |
| 输出质量 | 与当前 fp16 基线对齐 | 以同 seed 验收为准 |
| 图速度 | 常见约 +20%～30%（Sage） | 视分辨率 / 驱动 / 是否已用高效 Attention |
| 视频速度 | 采样阶段常见明显加速（Sage） | 若 BlockSwap 过大，墙钟可能被搬运抵消 |
| 显存 | 峰值下降、OOM 减少 | 靠调度，不靠量化 |
| 架构 | 零新服务 | 仍一个 `:8188` |

> 无损档**不可能**承诺 MagCache/Lightning 那种「接近砍半」的墙钟收益；那是有损档的能力边界。

## 4. 目标架构

### 4.1 不变的主链路

```text
用户对话
  → Agent 决定调用 generate_image / generate_video
  → snapshot_for(image_gen | video_gen)
  → ComfyUIAdapter / ComfyUIVideoAdapter
  → POST http://127.0.0.1:8188/prompt
  → 轮询 history → /view 取结果
  → 落盘 chat_images / chat_videos
  → tool_visual + assistant.visuals + Langfuse
```

### 4.2 变化只发生在 ComfyUI 进程内部

```text
image_gen/comfyui/                         # 仍 gitignore，不新起根目录
├── run_nvidia_gpu.bat（或 lazy command）   # + --lowvram [--use-sage-attention] [--reserve-vram]
├── python_embeded/                        # + sageattention + triton-windows
└── ComfyUI/
    ├── custom_nodes/                      # 可选：仅 offload/attention 所需节点
    │     └── ComfyUI-WanVideoWrapper/     # 仅启用 BlockSwap / T5 CPU / attention_mode
    │                                       # 禁止启用 MagCache/TeaCache 节点
    ├── models/…                           # 仍用现有 fp16 权重
    └── （无第二套引擎）
```

仓库内可进 git 的部分：

```text
workflows/
  sdxl_txt2img.json                 # 可保留；或仅靠启动参数加速
  wan21_t2v_1_3b.json               # 基线（可回退）
  wan21_t2v_1_3b_lossless.json      # 新增：fp16 + T5 CPU + 最小 BlockSwap（无 cache）
image_gen/
  setup_lossless_accel.ps1          # 新增：装 Sage/triton、可选拉节点、写启动参数
scripts/
  verify_local_gen_quality.py       # 新增：同 seed 回归
docs/
  本地生图生视频-无损性能优化方案.md  # 本文
```

### 4.3 配置项（建议）

在现有 `config.yaml` 语义上扩展（名称可微调，原则如下）：

| 键 | 建议默认 | 含义 |
| --- | --- | --- |
| `image_gen_comfyui_workflow` | 现有 SDXL 工作流 | 不改为 Lightning |
| `video_gen_comfyui_workflow` | `./workflows/wan21_t2v_1_3b_lossless.json`（落地后） | 可回退旧 JSON |
| `comfyui_launch_extra_args` | `--lowvram --use-sage-attention` | 写入 lazy/command 或 bat |
| `comfyui_quality_mode` | `lossless` | 文档与门禁用；`lossy` 预留且默认关闭 |
| `video_gen_block_swap` | 整数，**从 0 标定** | 仅升到「刚好不 OOM」 |
| `video_gen_t5_on_cpu` | `true`（8GB 建议） | 文本编码卸 CPU |

**门禁**：当 `comfyui_quality_mode=lossless` 时，Adapter 或启动前检查工作流 JSON，若出现 MagCache/TeaCache/`UnetLoaderGGUF` 等禁止节点 → 拒绝提交并打明确错误（避免误配有损模板）。

## 5. 分项设计

### 5.1 SageAttention（算子加速）

| 项 | 说明 |
| --- | --- |
| 作用 | 用高效 8bit Attention kernel 加速，不改扩散步数与权重 |
| 安装位置 | ComfyUI 便携包 **同一** `python_embeded\python.exe` |
| 依赖 | `sageattention` + Windows 上通常需要 `triton-windows`（版本须匹配 Torch/CUDA） |
| 启用 | 启动参数 `--use-sage-attention`；若使用 WanVideoWrapper，在 loader 上选 `sageattn`（Wrapper 可能不吃全局 flag） |
| 失败策略 | 导入失败则回退 SDPA/默认 Attention，**不得**改 steps 或换量化模型凑数 |
| 回滚 | 去掉启动参数 / 节点选项即可 |

### 5.2 `--lowvram` / `--reserve-vram`（通用显存调度）

| 项 | 说明 |
| --- | --- |
| 作用 | ComfyUI 按需把模块装上 GPU，降低峰值 |
| 质量 | 同一推理图，结果应与 full load 一致 |
| 代价 | 可能略增耗时（模块来回） |
| 建议 | 8GB 默认开 `--lowvram`；若与桌面抢显存，可加 `--reserve-vram 1`～`2` 做保护（按实机标定） |

### 5.3 Wan：T5→CPU + 最小 BlockSwap（视频峰值）

| 项 | 说明 |
| --- | --- |
| T5/UMT5 → CPU | 文本编码很大；放到 CPU 显著降峰值，不改采样数学 |
| BlockSwap | 仅交换必要 transformer blocks；**标定原则：从 0 递增到刚好稳定** |
| prefetch | 可用 `1` 缓解 swap 带来的速度损失 |
| 禁止 | 同时叠加重度 VRAM management + 过大 swap「为了更快」——本方案目标是稳与质量，不是极限抠显存 |
| 系统内存 | 建议 ≥32GB，否则 offload 会抖 |

> 若当前原生工作流（无 Wrapper）在 8GB 上已稳定：P1 可只上 Sage + `--lowvram`，P2 再引入 Wrapper 的 offload 节点，降低一次变更风险。

### 5.4 运行卫生（已有规则强化）

| 规则 | 要求 |
| --- | --- |
| 单引擎 | 图视频共用一个 ComfyUI，禁止第二便携包常驻 |
| 串行 | 同轮禁止「出图成功又出视频成功」；队列天然串行亦须在产品层保持 |
| 占用人 | 生成前关闭向日葵 / ToDesk 等；Agent/工具错误文案可提示 |
| 常驻 | 避免每次请求重启 ComfyUI；`ensure_comfyui` 仅在未就绪时拉起 |
| 模型切换 | 少在图/视频权重间无谓来回切，减少反复装载 |

### 5.5 Adapter 行为（质量锁）

`ComfyUIAdapter` / `ComfyUIVideoAdapter`：

- **继续**按请求改写：prompt、negative、seed、size、frames、steps（steps 来自配置默认，不因优化模式减少）。  
- **可增加**对 offload 相关 `class_type` 的识别（如 BlockSwap 参数来自 config）。  
- **不得**因 `lossless` 模式改写 sampler/cfg/降低 size。  
- `model_id` 主路径应指向 fp16 safetensors；若用户手动填 `.gguf`，在 `lossless` 模式下告警或拒绝（产品可选：拒绝更严）。

## 6. 端到端行为（用户视角）

1. 用户说「画一只橘猫」→ 与现网相同工具调用 → 本地 SDXL 出图。  
2. 用户说「生成一段橘猫晒太阳的短视频」→ 与现网相同 → 本地 Wan 出片。  
3. 差异仅可能是：等待时间变化、OOM 更少；**文案不必承诺「画质升级」**，可写「本地引擎性能优化（不影响画质）」。  
4. ComfyUI 未装好 Sage 时：应仍能出图/出视频（回退 Attention），并在日志中明确「Sage 未启用」。

## 8. 回滚策略

| 层级 | 动作 | 预期 |
| --- | --- | --- |
| L1 | 去掉 `--use-sage-attention` | 回退默认 Attention |
| L2 | 去掉 `--lowvram` | 恢复全量驻留（若显存够） |
| L3 | `video_gen_comfyui_workflow` 改回 `wan21_t2v_1_3b.json` | 去掉 Wrapper/offload 节点依赖 |
| L4 | 卸载 sageattention（可选） | 环境回到安装前 |

回滚**不得**通过启用 GGUF/MagCache/Lightning「顶上」——那会变成有损档，违反本方案。

## 9. 验收标准（必须全过）

| # | 标准 | 失败处理 |
| --- | --- | --- |
| Q1 | 同 seed 图/视频与基线 SSIM（或约定指标）达标 | 关闭最近引入的开关，禁止带回归发布 |
| Q2 | 默认 steps/size/duration/fps/cfg/sampler 未变 | 改回配置 |
| Q3 | 主路径权重仍为 fp16 safetensors | 移除 GGUF 默认 |
| Q4 | 工作流无 MagCache/TeaCache 等跳步节点 | 换回 lossless 模板 |
| Q5 | 对话出图/出视频、取消、超时、落盘、SSE 行为与现网一致 | 修 Adapter / 工具层 |
| Q6 | Sage 安装失败时仍可生成（降级 Attention） | 修失败策略 |
| P1 | 至少在一套实机上记录优化前后耗时与峰值显存 | 写入本节附录或测试日志 |

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Windows 上 Sage/triton 版本不匹配 | 启动失败或无效加速 | 锁 wheel 版本；失败降级；文档写明 Torch/CUDA |
| BlockSwap 过大 | 变慢明显 | 标定最小 swap；prefetch=1 |
| 引入 custom_nodes 后节点缺失 | 视频全失败 | P1 先只改启动参数；P2 安装校验 + 健康检查列节点 |
| 系统内存不足 | offload 抖动/变慢 | 文档要求 ≥32GB；内存不足时提示，不自动量化 |
| 误把有损工作流配进 lossless | 质量下降 | JSON 门禁 + `quality_mode` |
| 期望「再快一倍」 | 预期落差 | 产品说明写清：无损档收益上限；有损档另案 |

## 12. 与「有损加速」的边界（预留，不实施）

以下手段**明确排除在本方案交付之外**。若产品日后接受可感知质量损失，应另开文档（例如「本地有损加速档」），并与 `comfyui_quality_mode=lossy` 隔离配置，避免与无损档混用：

- Wan/SDXL GGUF 量化主路径  
- MagCache / TeaCache  
- SDXL-Lightning / 少步蒸馏  
- 默认规格再降档

## 14. 决策摘要

| 决策 | 结论 |
| --- | --- |
| 质量 | **硬约束**：参数、权重、步数路径不变；禁止量化与跳步 |

## 附录 B · 与现有视频方案表述的关系

[`文生视频完整产品方案.md`](./文生视频完整产品方案.md) 中曾将 **GGUF** 写为 8GB 主路径推荐。
