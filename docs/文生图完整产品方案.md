# 文生图完整产品方案

> Second Person · 本地 ComfyUI + SDXL · 一次一张 · 与现有 Agent 工具环 / SSE / `chat_images` / Langfuse 对齐  
> 版本：2026-09-10（RTX 3070 8GB）

## 产品一句话

对话模型（chat/agent）只负责「要不要画、画什么」；真正出图由独立 **`image_gen` 槽位** 调 **本地 ComfyUI（SDXL）**。图立刻落本地 `chat_images`，经 `tool_visual(type=generated_image)` 推前端，并写入本轮 `assistant.visuals`；Langfuse 记工具 span + 独立 generation，**不上报像素本体**。

| 项 | 值 |
| --- | --- |
| 主路径 | 工具 `generate_image` |
| 出图引擎 | **本地 ComfyUI + SDXL** |
| 槽位 | `image_gen`（**无** chat/agent 回退） |
| 默认张数 | **1** |
| 单次上限 | **1**（V1 锁死；不做 batch） |
| 默认尺寸 | `1024x1024` |
| 超时 | **180s** |
| 文件名前缀 | `gen_` |
| 前端地址 | 只用本站 `/chat-images/...` |

## 1. 角色拆分

| 角色 | 用哪个模型/槽 | 职责 | 禁止 |
| --- | --- | --- | --- |
| 对话 Agent | chat / agent（现有） | 理解意图；决定是否调用工具；把用户中文需求整理成清晰出图描述；出图后写说明文案 | 自己编造图片 URL；把像素当文本输出 |
| 文生图服务 | 新槽 `image_gen` → **ComfyUI Adapter** | 只接收结构化参数，调本地 ComfyUI 工作流，返回图文件 | 参与多轮对话；读记忆；调其他工具 |
| 宿主（后端） | 无模型 | 校验参数、调 Adapter、落盘、发 SSE、写 DB、打点 Langfuse | 把 ComfyUI 临时路径直接暴露给前端 |
| 前端 | 无模型 | 展示 tool 进度（含耗时预期）；渲染 `generated_image`；历史从 `visuals` 恢复 | 自行拼 `127.0.0.1:8188` 之类本地地址 |
| ComfyUI（外部进程） | SDXL checkpoint | 真正扩散推理 | 不由 Second Person 内嵌进同一进程（V1） |

**槽位规则：** `image_gen` 不得 fallback 到 chat/agent。未配置或 ComfyUI 不可达时，工具返回明确错误，由 Agent 用文字告知——避免对话模型胡编图。

**产品骨架：** Agent 工具主路径 → Adapter → `chat_images` 落盘 → `tool_visual` / `visuals` 双通道；不新增专用 HTTP，仍走 `/api/chat/send` + 工具环。

## 2. 端到端时序（一次一张）

场景：用户说「画一只趴在窗台的橘猫」。

| 步骤 | 谁 | 做什么 |
| --- | --- | --- |
| T0 | 前端 | `POST /api/chat/send`，body 与平时相同。**不新增**「生图专用」HTTP；**不在前端指定工具**。 |
| T1 | 宿主 | 进入 `TurnRuntime`；SSE `turn_started` / `step_started`；组装 system + tools（含 `generate_image`）。 |
| T2 | 对话模型 | `source=agent_step`。判定需要出图 → `tool_calls: generate_image`（`n` 固定按 1 处理）。 |
| T3 | SSE | `tool_executing`：`{tool_name:"generate_image", status:"running", …}`；前端文案：「正在本地生成图片，可能需要十几秒…」 |
| T4 | 工具执行 | 校验参数 → `snapshot_for("image_gen")` → **ComfyUI Adapter**：提交工作流 / 等待完成 / 取图 bytes → 写入 `data/chat_images/gen_*.png`。 |
| T5 | SSE（双通道） | ① `tool_result`；② `tool_visual type=generated_image`。 |
| T6 | 回灌模型 | `role=tool` 短 JSON（`public_urls` / `filenames` / `latency_ms`），**不含** base64。 |
| T7 | 对话模型 | 再一步写一句说明；`content_delta`。 |
| T8 | 落库终态 | `assistant.visuals` 含 `generated_image`；`turn_completed`。 |

**并行约定（V1）：**

- 禁止 batch / 禁止同一步多个 `generate_image` 并行
- 若模型误传 `n>1`：**夹紧为 1**，summary 说明「当前本地模式一次只生成 1 张」
- 用户要第二张：新一轮对话再调一次工具
- 同轮最多 **1** 次成功出图

## 3. 来回链路对齐表

| 阶段 | 上游输入 | 下游输出 | 对齐键 |
| --- | --- | --- | --- |
| 用户 → 后端 | `ChatSendRequest.message` | conversations 用户行 + turn | `session_id` / `client_request_id` |
| Agent → 工具 | OpenAI `tool_call.function.arguments` | ToolExecutor 入参 dict | `call_id` |
| 工具 → ComfyUI | 规范化 `ImageGenRequest` | 本地工作流 prompt_id / 图像 bytes | `provider_id` + `model_id`（如 `sdxl-local`） |
| ComfyUI → 本地文件 | bytes | `gen_{12hex}.png` | `filename` |
| 工具 → 模型下一步 | `ImageGenResult` 短 JSON | `role=tool` content | `call_id` → `tool_call_id` |
| 工具 → 前端实时 | 同一 `ImageGenResult` | SSE `tool_result` + `tool_visual` | `turn_id` + `call_id` |
| 终态 → 历史 | `turn_visuals[]` | `conversations.visuals` | `message_id` |

**对齐原则：**

- 模型通道只传短元数据
- 像素只走落盘 + `tool_visual` / `visuals`
- 禁止 data URI 进 tool role
- 禁止前端直连 ComfyUI（`127.0.0.1:8188` 等）
- Adapter 统一出口是 `ImageGenResult`；日后若接其他后端，只换 Adapter，不改 SSE / 前端 / 落盘

## 4. 参数规则（3070 + SDXL）

### 产品默认（V1）

- `n` 默认 = **1**，上限 = **1**
- `size` 默认 = **`1024x1024`**；V1 仅允许该尺寸（其他请求映射回默认）
- steps 默认 = **24**（可配置，建议 20–28）
- CFG / sampler：写在 ComfyUI 工作流模板里，**不开放给 Agent**（V1）
- 超时 = **180s**
- 同轮：最多完成 **1** 次成功出图
- 用户说「出多张」：Agent 说明「当前一次一张」，需要则再开一轮各画一张

### `config.yaml` 键

```yaml
image_gen_backend: comfyui
image_gen_default_n: 1
image_gen_max_n: 1
image_gen_turn_max_images: 1
image_gen_default_size: "1024x1024"
image_gen_timeout_sec: 180
image_gen_prompt_max_chars: 1500
image_gen_steps: 24
image_gen_comfyui_base_url: "http://127.0.0.1:8188"
# 引擎根目录：仓库内 image_gen/comfyui/（整目录 gitignore，类似 embedding/models）
image_gen_comfyui_root: "./image_gen/comfyui"
image_gen_comfyui_workflow: "./workflows/sdxl_txt2img.json"
```

### 工具参数 schema

```text
generate_image
required: [prompt]
properties:
  prompt: string       # 出图描述；V1 建议英文（可由 Agent 或润色步骤产出）
  negative_prompt: string  # 可选；缺省用工作流内置负面词
  size: string         # V1 仅接受 1024x1024；其他值服务端映射
  # n 仍可出现在 schema，但服务端强制夹紧为 1
  style_hint: string   # photo|illustration|sketch|anime → 并入 prompt 前缀
```

## 6. 前后端统一契约

### 6.1 `ImageGenResult`

```js
ImageGenResult = {
  type: "generated_image",
  filenames: string[],      // V1 长度恒为 1
  public_urls: string[],    // 长度恒为 1
  n: 1,
  revised_prompt?: string,
  negative_prompt?: string,
  size: "1024x1024",
  provider_id: string,
  model_id: string,         // 如 "sdxl-local" / checkpoint 名
  latency_ms?: number,
  backend: "comfyui",
  summary: string           // 如「已本地生成 1 张图（SDXL，约 18s）」
}
```

### 6.2 SSE

现有事件集合不变；前端文案与超时预期适配本地耗时（常见 10–40s，冷启动更久）。

**白名单：** `generate_image` 必须进入 `tool_visual` 发射白名单。

### 6.3 前端

- `generated_image` → 单张大图（V1 不做多图网格）
- 时间线：生成中提示「本地 SDXL，可能需要十几秒到几十秒」
- 失败时不发 `tool_visual`

### 6.4 设置页 / Provider

`TASK_SLOTS` 增加 `image_gen`：「文生图模型（本地 ComfyUI）」。

| 字段 | 示例 |
| --- | --- |
| `provider_type` | `comfyui` |
| `base_url` | `http://127.0.0.1:8188` |
| `model_id` | SDXL checkpoint 名 |
| `api_key` | 可空 |

`test-connection`：**GET ComfyUI `/system_stats` 或 `/queue`**，确认进程存活，而不是用 chat probe。

## 7. Prompt 规则

### A. 工具族规则 `base_rules_image_gen.md`

- 用户明确要求画/生成/绘/出图时才调用
- **一次只生成 1 张**；用户要更多 → 说明后新一轮再调
- prompt 写具体可见描述（主体、场景、光线、构图、风格）
- **优先英文 prompt**；若用户给中文，Agent 先译成简洁英文再调用（或走润色）
- 不要塞隐私信息
- 成功后一两句中文说明即可；不伪造外链、不输出 base64
- ComfyUI 未启动 / 未配置时诚实说明，引导启动本地服务或检查设置

### B. 润色（P0.5）

- `image_prompt_refine`：中文短句 → SDXL 友好英文 + 可选 negative_prompt
- `source="image_prompt_refine"`；失败则回退 Agent 原始 prompt 仍出图

原因：本地 SDXL 对英文提示更稳，润色对出图质量影响大。

## 8. Langfuse

挂在现有 `agent.turn` 下。只记 prompt / 张数 / 耗时 / 文件名，不上报像素。

| 观测 | name | 记录内容 |
| --- | --- | --- |
| span | `tool_execute` | tool 名、prompt preview、ok、filenames、n、latency |
| generation | `llm.image_gen` | prompt、size、steps、model_id、backend=`comfyui`、latency_ms、filenames；**无像素**；`image_count=1` |
| generation（P0.5） | `llm.image_prompt_refine` | 短句 → 润色结果 |

## 9. 错误与边界

| 情况 | 工具返回 | 用户感知 |
| --- | --- | --- |
| 未配置 `image_gen` | `ok:false` | 引导去设置页 |
| ComfyUI 未启动 / 连接失败 | `ok:false`「本地生图服务未启动」 | 提示先打开 ComfyUI |
| 显存不足 / ComfyUI 报 OOM | `ok:false` | 建议关掉占显存程序后重试；不要静默降质量乱试 |
| 超时（>180s） | `ok:false` | 可重试；检查是否卡在队列 |
| `n>1` | 夹紧为 1 并说明 | 「当前一次只生成 1 张」 |
| 取消 turn | 尽量取消 ComfyUI 队列任务（若 API 支持）；已落盘保留 | 与现有取消一致 |
| 远程桌面占显存 | 不自动处理 | 文档/错误文案可提示：生图前尽量关闭远控 |

## 11. 目录布局（仓库内 `image_gen/`）

原则：**生图引擎放在 `Second-Person` 项目目录内**，与产品同根；大体积 ComfyUI 与模型权重用 `.gitignore` 隔离（风格对齐已有 `embedding/models/`）。**不要**把引擎散放到仓库同级，也不要塞进 `data/`。

```text
D:\project\Second-Person\
├── data\chat_images\              # 对话落盘图：img_* / gen_*（用户数据，已 ignore）
├── workflows\                     # 小体积工作流 JSON（可进 git）
│   └── sdxl_txt2img.json
├── image_gen\                     # 本地生图根目录
│   ├── README.md                  # 启动说明（可进 git）
│   └── comfyui\                   # ComfyUI 便携包整包（gitignore）
│       ├── run_nvidia_gpu.bat
│       ├── models\checkpoints\
│       │   └── sd_xl_base_1.0.safetensors   # ~6.5GB+
│       └── output\                # ComfyUI 临时输出（可定期清理）
├── docs\文生图完整产品方案.md
└── .gitignore                     # 必须包含 /image_gen/comfyui/
```

| 路径 | 是否进 git | 用途 |
| --- | --- | --- |
| `Second-Person\` | 是 | 产品代码 |
| `data\chat_images\` | 否（`/data/`） | 给前端看的最终图 |
| `workflows\` | 是（仅 JSON） | 调用 ComfyUI 的工作流模板 |
| `image_gen\README.md` | 是 | 本机部署说明 |
| `image_gen\comfyui\` | **否** | 引擎 + SDXL 权重 |

**不要：**

- `D:\project\ComfyUI\`（与仓库分离，目录散乱）
- `Second-Person\data\comfyui\`（`data/` 是用户数据备份单元，不是引擎）
- 把 `image_gen\comfyui\` 提交进 git

## 决策摘要

1. **引擎：本地 ComfyUI + SDXL**
2. **张数：严格一次一张**
3. **目录：仓库内 `image_gen/comfyui/`**（gitignore；最终图仍在 `data/chat_images/`）
4. **产品骨架：** 工具 → Adapter → 落盘 → `tool_visual` → `visuals`
5. **必须补强：** ComfyUI 健康检查、180s 超时、英文 prompt/润色、OOM/未启动错误文案
6. **扩展：** 其他后端只换 Adapter，不进 V1 主路径
