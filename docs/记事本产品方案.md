## 1. 一句话定位

在 Second Person 内提供一等公民的**富文本记事本**：用户可对文档做完整增删改查，可**自行编辑文件夹/目录结构**做结构化管理，可在文档内查找与替换，正文支持多级标题、最多 10 级嵌套列表、加粗/斜体/下划线与插图；并可划词唤起侧边对话，以及让 AI 流式写回当前文档（写前备份可恢复）。

它不是 Notepad++ 克隆，也不是记忆宫殿或知识库；它是用户主动维护的**工作草稿区**，存储与备份跟现有 `data/` 体系一致，并与现有 Agent / 侧边会话能力打通。

## 2. 本期明确要做的范围

### 2.1 用户诉求（验收主线）

| 维度 | 要求 |
| --- | --- |
| **增** | 创建文档（含默认标题、空正文） |
| **删** | 删除文档（需确认；可软删或直接删除，见 §6） |
| **改·名** | 修改文档名称（标题） |
| **改·内容** | 编辑正文并持久化 |
| **查·列表** | 浏览已有文档并打开 |
| **查·文内** | 在当前文档内容中搜索关键字 |
| **替换** | 在当前文档内将匹配文字替换为指定文字（单次 / 全部） |
| **富文本** | 见 §4 |
| **划词侧边对话** | 选中正文后唤起侧边会话；浮条仅 **复制 + 侧边会话**（见 §5.8） |
| **AI 写文档** | 侧边对话后可直接改当前文档；**流式写入编辑器**；写前备份、可随时恢复（见 §5.9） |
| **插图** | 正文可插入图片，随文档持久化与展示（见 §4.5 / §6） |
| **目录结构** | 用户自建/重命名/移动/删除文件夹；文档归入目录；左侧树形管理（见 §5.10） |

### 2.2 从 Notepad++ 调研中「借鉴的产品心智」（仅概念）

对照能力全景，本期只吸收与主线直接相关的体验，不展开 N++ 全量能力：

| 借鉴点 | 对应 N++ 能力域 | 在本期的落地形态 |
| --- | --- | --- |
| 文档实体与编辑区分离 | Buffer / FileManager | `Note` 实体 + 编辑器视图 |
| 多文档切换 | DocTab / 多文档标签 | 左侧目录树内点选打开 |
| 文件夹式组织 | Folder as Workspace / Project Panel（弱化借鉴） | **用户可编辑的笔记目录树**（非扫盘工作区） |
| 脏状态与保存 | 脏标记 `*`、保存 | 自动保存 + 未保存提示（关闭/切换时） |
| 文内查找替换 | Find / Replace（单文档） | 编辑器内查找条 / 替换条 |
| 会话式「回到上次」 | Session（弱化） | 记住上次打开的文档 ID（P1，不进首发） |

**AI 联动**不属于 N++，属于 Second Person 差异化：划词侧边会话复用现有 `SelectionActionBar` + `SideChatDrawer` 产品定稿；写回文档走宿主工具，不绕过沙箱与契约。

**明确不纳入本期**（相对能力全景）：双视图、多实例、宏、插件、Find in Files、语法高亮百语言、列块编辑、打印、编码/EOL 全家桶、工程面板、命令行等。若后续扩展，另开版本，不以本期阻塞。

### 2.3 与现有产品边界

```text
记事本 Note          ≠  Chat 输入草稿 composerDraft
                     ≠  记忆宫殿 memories（需确认的长期事实）
                     ≠  知识库 raw_docs（导入资料）

记事本侧边会话        =  复用现有 aside 语义（channel='aside'，不进主列表/搜索）
                     ≠  主对话会话；关闭/刷新后前端不恢复历史（与现网一致）
```

本期**不做**自动写入记忆/知识库；与对话的联动以 §5.8 / §5.9 为准（划词侧边 + AI 写回），不再列为可选项。

## 3. 用户故事与主流程

### 3.1 核心故事

1. **作为用户**，我可以新建一篇文档并开始写内容，刷新后内容还在。  
2. **作为用户**，我可以重命名文档，列表与打开态标题同步更新。  
3. **作为用户**，我可以删除不再需要的文档。  
4. **作为用户**，我可以在列表中找到文档并打开继续编辑。  
5. **作为用户**，我可以在正文里查找某段文字，并逐个或全部替换。  
6. **作为用户**，我可以用标题层级、有序/无序列表（可嵌套）、加粗/斜体/下划线组织内容，且打开后样式正确呈现。  
7. **作为用户**，我可以在文档里划词，弹出操作条，并打开**侧边会话**就这段内容继续聊（可附评论）。  
8. **作为用户**，我可以在侧边会话里让 AI **流式改当前文档**，并可用备份恢复 AI 改前版本。  
9. **作为用户**，我可以**自己建文件夹、改名、嵌套、移动文档**，用目录树结构化管理笔记。

### 3.2 主界面信息架构

建议新增独立路由 **`/notes`**（与 `/chat` `/memory` `/settings` 并列），页面结构：

```text
┌──────────────────────────────────────────────┬──────────────────┐
│  记事本     [+ 新建文件夹] [+ 新建文档]        │                  │
├──────────────┬───────────────────────────────┤  侧边会话抽屉     │
│ 目录树        │  标题（可点改）                 │                  │
│ ▼ 工作        │  工具栏 · 插图 · 查找/替换      │                  │
│   · 周报      │───────────────────────────────│                  │
│   ▼ 项目A     │  富文本编辑区（可划词）          │  ChatView       │
│     · 需求稿  │  选区 → 浮条：复制 / 侧边会话   │  asideMode      │
│ · 未命名文档  │                               │                  │
│ （根目录/未分类）                              │                  │
└──────────────┴───────────────────────────────┴──────────────────┘
```

- 左侧：**可编辑目录树**（文件夹 + 文档；展开/折叠；拖拽或菜单移动）。  
- 中间：当前文档的标题 + 富文本编辑器 + 查找替换入口。  
- 右侧：划词侧边会话抽屉（复用现网组件）。  
- 视觉：遵循 SP-UI v4。

## 4. 富文本能力规格（本期硬性）

### 4.1 必须支持的格式

| 能力 | 规格 |
| --- | --- |
| 多级标题 | 至少 **H1–H6**（「多级标记」按六级标题实现；与常见富文本/Markdown 对齐） |
| 无序列表 | 支持，**嵌套最多 10 级** |
| 有序列表 | 支持，**嵌套最多 10 级**；有序/无序可互相嵌套，总深度上限 10 |
| 加粗 | 支持 |
| 斜体 | 支持 |
| 下划线 | 支持 |
| 正文段落 | 默认段落；Enter 换段，Shift+Enter 软换行（实现时与编辑器默认对齐并写进帮助提示） |
| 插入图片 | 支持（工具栏/粘贴/拖入）；见 §4.5 |

### 4.2 交互要求

- 提供**可见工具栏**（或气泡菜单 + 工具栏），一键应用标题级别、列表、粗/斜/下划线。  
- 快捷键（建议，可与编辑器默认对齐后写入说明）：  
  - Ctrl+B 加粗 · Ctrl+I 斜体 · Ctrl+U 下划线  
  - Ctrl+F 查找 · Ctrl+H 替换（或 Ctrl+Alt+F，最终以不与全局冲突为准）  
  - Tab / Shift+Tab：列表升降级（不超过 10 级时提示或忽略）  
- 超过 10 级嵌套：**禁止再升一级**，并 Toast 提示「列表最多支持 10 级」。

### 4.3 存储格式选型（产品决策）

为贴合本仓库「**md 文件为主副本**」与富文本诉求，采用：

| 决策 | 说明 |
| --- | --- |
| **主副本格式** | **Markdown**（GFM 子集 + 下划线扩展） |
| **下划线** | 标准 MD 无下划线；采用 HTML `<u>…</u>` 或编辑器约定语法，读写往返一致即可 |
| **运行时** | 前端富文本编辑器（WYSIWYG）编辑；保存时序列化为 Markdown 写入磁盘 |
| **打开时** | Markdown → 编辑器文档模型 |

**不采用**纯纯文本 Notepad++ 模型作为主交互；N++ 调研仅指导文档生命周期与查找替换心智。

备选（若实现评估 WYSIWYG 过重）：「分栏 MD 源码 + 预览」——**不作为本期首选**，因用户明确要求富文本输出与样式操作。

### 4.4 编辑器技术方向（实现指引，非绑定某一库）

| 方向 | 适用性 |
| --- | --- |
| **ProseMirror / TipTap 类** | 与标题、列表嵌套、标记样式最契合，**首选方向** |
| CodeMirror 6 | 更偏源码编辑；若强行走 MD 源码模式，工具栏体验弱于诉求 |
| 浏览器 `contenteditable` 裸写 | 不推荐，列表层级与序列化成本高 |

具体库版本在实现评审时锁定；产品只要求能力达标与 MD 可往返。

### 4.5 插入图片（本期必达）

| 项 | 规格 |
| --- | --- |
| 入口 | 工具栏「插入图片」；支持粘贴剪贴板图片；支持拖入图片文件 |
| 展示 | 编辑区与再打开后均可正常显示 |
| 格式 | 常见栅格图：png / jpg / jpeg / gif / webp |
| 大小 | 单张建议上限与现有聊天附图策略对齐（实现时定具体 MB）；超限拒绝并提示 |
| 在 MD 中的形态 | `![alt](相对或可解析的资源路径)`，资源文件落在笔记资源目录（见 §6） |
| 删除 | 从正文删除图片节点后，对应资源文件可惰性清理或随保存 GC（实现选定一种，避免立刻误删可恢复备份里仍引用的图） |

## 5. CRUD 与查找替换：功能细则

### 5.1 创建（增）

- 入口：「新建文档」按钮。  
- 默认标题：**`未命名文档`**（允许与其它文档同名，不强制递增后缀）。  
- 默认正文：空段落。  
- 创建后立即进入编辑态并落盘（或先内存再首次自动保存，但刷新不得丢）。

### 5.2 列表与打开（查）

- 列表展示：标题、更新时间（相对或绝对，中文）。  
- 点击打开；同时仅一个「当前文档」处于编辑焦点。  
- 列表按标题过滤：**不进本期**（P1）。

### 5.3 重命名（改·名）

- 方式：点击标题内联编辑，或列表项「重命名」。  
- 校验：非空；去首尾空白；长度上限建议 120 字；禁止纯空白。  
- 重名：允许（靠 ID 区分）。

### 5.4 编辑内容（改·内容）

- 编辑即产生本地脏状态；**防抖自动保存**（建议 800–1500ms）到服务端。  
- 保存失败：Toast + 保留脏状态，可手动「重试保存」。  
- 工具栏操作与键盘输入同等进入撤销栈（编辑器原生 Undo/Redo）。

### 5.5 删除（删）

- 需二次确认（`BaseModal` / 全局 confirm）。  
- 删除当前文档后：自动打开列表中下一篇，或展示空状态「暂无文档」。  
- **本期建议物理删除**文件；若需回收站，列为二期。

### 5.6 文内搜索（查·内容）

- 范围：**仅当前打开文档**（不是跨文档、不是全库；跨文档属 N++ Find in Files，本期不做）。  
- 能力：关键字高亮、上一个/下一个、匹配计数。  
- 选项（P0 最小集）：区分大小写（开关）；整词匹配可作 P1。  
- 正则：**本期不做**（N++ 强项，但不在用户本期诉求内）。

### 5.7 替换

- 与查找同一面板：替换为…、替换、全部替换。  
- 全部替换后给出数量反馈（「已替换 N 处」）。  
- 替换结果进入撤销栈，支持 Ctrl+Z 撤回。  
- 空「查找」内容时禁用替换。

### 5.8 划词唤起侧边对话（与现网逻辑对齐）

**产品原则：交互与现有 Chat 划词侧边会话一致，记事本页只换「选区来源」，不另发明一套。**

#### 5.8.1 现网已定稿语义（必须保持）

与 `SideChatDrawer` / `SelectionActionBar` / Chat 划词流程对齐：

| 点 | 行为 |
| --- | --- |
| 选区浮条 | 记事本页仅 **复制 / 侧边会话**（两键；不做「引用」键，避免与 Chat 三键混淆） |
| 侧边会话 | 右侧抽屉滑出；内部复用 `ChatView(asideMode)` |
| 打开前 | 可先弹出与现网相同的**评论录入弹窗**，确认后再把选区 + 评论注入侧边输入区（**不自动发送**） |
| 会话归属 | `channel='aside'`；**不进**主会话列表 / 会话搜索 |
| 数量 | 同一绑定主体至多一个 open 侧边；再次划词 → **追加引用到已开侧边**，不新开第二个抽屉 |
| 关闭 | 用户点 X 关闭或刷新 → 前端销毁，不显历史（后端可留痕，前端不管） |
| 侧边内划词 | 侧边内部选区 **不再套娃**「侧边会话」按钮（`showAside=false`） |

#### 5.8.2 记事本页的绑定主体

现网 aside 绑定的是「发起它的**主会话**」。记事本无主会话，本期约定：

| 项 | 约定 |
| --- | --- |
| 绑定键 | **当前打开的 `note_id`**（一文档一 aside；切换文档时：当前文档的抽屉按「切主会话」同理——隐藏并保活，切回未关闭者继续显示） |
| 路由放开 | `App` / `SideChatDrawer` 现仅在 `/chat` 显示；需扩展为 **`/notes` 同样允许**打开与显示侧边抽屉 |
| 来源标记 | 创建 aside 会话时带上来源：`from_note=<note_id>`（或等价字段），便于后端与观测归组；与现有 `from_session` 并列，二选一或可同时存在时以实现为准 |
| 项目继承 | 若笔记将来绑定 `project_id`，aside 继承该项目；本期笔记全局则可无项目 |

#### 5.8.3 浮条按钮（已确认）

| 按钮 | 行为 |
| --- | --- |
| **复制** | 复制纯文本选区（与现网一致） |
| **侧边会话** | 与现网相同：可先评论录入弹窗，确认后 `openAside(quote)`，**不自动发送** |

选区文本：取编辑器选区的**纯文本**（不含不可见控制符）；过长时与现网一致做截断/提示。

#### 5.8.4 上下文注入（质量优先，已确认）

侧边会话每轮应对模型可见（经现有 `context.*` / Prompt 装配，前端不越权拼系统提示），**按完整能力做，质量优先**：

- 当前笔记 `note_id`、标题  
- 用户划词原文（引用附件/消息）  
- **笔记全文或分段正文**（超长时按 token 预算做结构化摘要 + 选区前后文窗口，优先保证选区邻域完整，再压缩远端章节）  
- 若正文含图片：注入时带图片占位说明（alt / 相对路径），避免模型误以为无图

### 5.9 AI 直接在文档上写内容

**目标：** 用户不只「聊关于文档的事」，还能让 AI **改文档本身**；改动出现在编辑器中，可继续人工编辑，并进入同一套自动保存 / 撤销体系。

#### 5.9.1 用户可感知场景

| 场景 | 示例 |
| --- | --- |
| 扩写选区 | 划词 → 侧边说「把这段扩写成三段」→ 选区被替换为扩写结果 |
| 改写选区 | 「改得更正式」→ 替换选区 |
| 插入 | 光标处或文档末尾「写一个会议议程」→ 插入块 |
| 全文结构生成 | 空文档或指定标题下「按大纲写一节」→ 写入对应位置 |
| 格式化整理 | 「把下面整理成三级标题 + 有序列表」→ 写回仍为合法富文本/MD |

#### 5.9.2 写回方式（产品约束，已确认）

| 约束 | 说明 |
| --- | --- |
| **唯一写入口** | 通过宿主注册的 **笔记工具**（如 `notes_apply_edit`）写盘/写缓冲，模型不能直接碰任意路径绕过笔记 API |
| **操作原语** | ① `replace_selection` ② `insert_at_cursor` ③ `append` ④ `replace_document`（允许对话后直接改全文） |
| **内容形态** | 工具写入 **Markdown**（可含图片引用）；前端走同一 MD→编辑器管道 |
| **写回形态** | **流式打进编辑器**（P0）：用户能看到内容逐步出现；流式结束后落盘并刷新 `updated_at` |
| **可见性** | 流式过程中编辑区实时更新；结束后可短暂高亮变更区（P1 打磨） |
| **备份与恢复（硬性）** | 每次 AI 成功改写前（或一轮写回开始前）对**上一版正文**做备份；用户可**随时恢复到备份版**（见 §6.4）。短撤销仍可用 Ctrl+Z；备份解决「整篇/大段改写后仍要回到 AI 改前」 |
| **并发** | 流式写回进行中对该文档加「AI 编辑中」锁，完成后解锁 |
| **确认策略** | 用户已在侧边下指令后即可写回（含整篇）；依赖备份+恢复兜底，不强制每次弹窗（避免打断流式体验） |

#### 5.9.3 与侧边会话 / 主对话的关系

| 路径 | 说明 |
| --- | --- |
| **主路径（本期）** | 记事本划词 → 侧边会话 → 模型写回当前文档（流式） |
| **主对话改笔记** | **本期不做**（工具不在主对话暴露；仅记事本侧边可写） |
| **Langfuse** | 侧边一轮一条 `agent.turn`；写笔记为同 trace 下 span，禁止旁路 trace |

#### 5.9.4 失败与边界

- 笔记不存在 / 已删除 → 工具返回明确错误，侧边可见。  
- 超过体积上限 → 拒绝写入并提示。  
- 列表深度等富文本约束：模型输出不合法时，应用层尽力解析；无法保证 10 级时降级为可解析结构并在工具结果中说明。  
- 用户关闭侧边不自动回滚已写入内容（已落编辑器/已自动保存的保留）；需要撤销用 Undo。

### 5.10 目录结构管理（用户自建，本期必达）

**目标：** 用户能像资源管理器一样维护「文件夹树」，把文档归类，而不是扁平一篇篇堆在一起。

#### 5.10.1 能力清单

| 操作 | 说明 |
| --- | --- |
| 新建文件夹 | 在根下或某文件夹下创建；默认名如「新建文件夹」（允许重名，靠 id 区分；展示上靠路径区分） |
| 重命名文件夹 | 内联或菜单改名 |
| 删除文件夹 | 需确认；**非空亦允许删**：确认后物理删除该文件夹及其全部子文件夹与文档（策略 A） |
| 嵌套 | 支持多级子文件夹；**建议深度上限 10 级**（与列表嵌套上限对齐，实现可配置） |
| 移动文件夹 | 拖拽或「移动到…」；禁止移入自身或子孙（环检测） |
| 新建文档时选位置 | 默认落在**当前选中文件夹**；若选中的是文档，则落在其父文件夹；根选中则落根 |
| 移动文档 | 拖到目标文件夹，或菜单「移动到…」 |
| 展开/折叠 | 树节点状态可本地记住（localStorage），不强制进服务端 |

#### 5.10.2 交互要点

- 左侧树同时展示**文件夹节点**与**文档叶子**（或文件夹内的文档列表）。  
- 右键或「⋯」菜单：新建子文件夹 / 新建文档 / 重命名 / 移动 / 删除。  
- 当前打开文档在树中高亮。  
- 空文件夹允许存在（便于先搭结构再写内容）。

#### 5.10.3 与 N++ 的关系

借鉴的是 Project Panel / Folder as Workspace 的「树形找文件」心智，**不是**扫本地任意磁盘目录；目录完全由用户在记事本内编辑，数据仍在 `data/notes/` 下。

## 6. 数据模型与存储

### 6.0 存储结论（答「数据库还是 md？」）

与 Second Person 现有记忆/项目一致，采用：

| 层 | 存什么 | 说明 |
| --- | --- | --- |
| **主副本：Markdown 文件** | 文档标题元数据 + 正文（含标题/列表/样式/图片引用） | **权威数据**；复制 `data/` 即备份 |
| **目录树元数据** | 文件夹层级、排序、文档归属 | **权威与 md 同级**（见 §6.2）；不是仅 UI 状态 |
| **二进制资源文件** | 插图等附件 | 与 md **分存** |
| **SQLite（可选派生）** | 列表/树索引加速 | **非权威**；可从文件重建 |
| **AI 修订备份** | AI 改写前正文 | 独立备份区（§6.4） |

**不把正文整篇只存在数据库里。**

### 6.1 实体

**`Folder`（文件夹）**

| 字段 | 说明 |
| --- | --- |
| `id` | 如 `fold_` + 短 hex |
| `name` | 显示名 |
| `parent_id` | 父文件夹；根下为 `null` |
| `sort_order` | 同级排序（可选） |
| `created_at` / `updated_at` | ISO 时间 |

**`Note`（文档）**

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定 ID，如 `note_` + 短 hex |
| `title` | 文档名称 |
| `folder_id` | 所属文件夹；根下未归类为 `null` |
| `body_md` | Markdown 正文（可含 `![](...)`） |
| `created_at` / `updated_at` | ISO 时间 |
| `project_id` | **本期可空** |

### 6.2 落盘约定（推荐：逻辑目录树 + 稳定 note 路径）

为避免「移动文件夹就整树改路径、弄乱图片相对引用」，**推荐**：

- 文档文件仍按 **`note_id` 稳定落盘**（移动目录只改归属，不改文件名路径）。  
- 目录结构写入独立权威文件（可被人类阅读/备份）。

```text
data/notes/
  _tree.json                   # 文件夹树 + 文档归属（权威之一）
  {note_id}.md                 # frontmatter: id, title, folder_id, created_at, updated_at
  {note_id}/                   # 该文档资源（有图才建）
    assets/
      {asset_id}.png
  _revisions/
    {note_id}/
      {rev_id}.md
      {rev_id}.meta.json
```

`_tree.json` 示意：

```json
{
  "folders": [
    {"id": "fold_a1b2c3d4", "name": "工作", "parent_id": null, "sort_order": 0},
    {"id": "fold_e5f6a7b8", "name": "项目A", "parent_id": "fold_a1b2c3d4", "sort_order": 0}
  ],
  "updated_at": "..."
}
```

文档归属以 **md frontmatter 的 `folder_id`** 为准；`_tree.json` 管文件夹节点与排序。二者不一致时：**以 md 的 `folder_id` + `_tree.json` 的 folders 合并校验**，孤儿文档归到根并告警（实现细则开工时定）。

**备选（不推荐作默认）：** 物理子目录镜像用户树（`data/notes/工作/项目A/xxx.md`）。浏览直观，但移动/重命名成本高、图片相对路径易碎——仅当产品强要求「资源管理器打开即见同名文件夹」时再议。

- md 内图片：`![说明](相对该 note 资源目录的路径)`。  
- SQLite 可选；若建表，须可从 `_tree.json` + md 重建。

### 6.3 大小与性能（产品上限）

| 项 | 建议 |
| --- | --- |
| 单文档 md 正文 | 告警 512KB；硬上限 2MB（纯文本体；不含图片二进制） |
| 单张图片 | 与聊天附图上限对齐（实现时定数） |
| 列表规模 | 首期按「数百篇」；分页二期 |

### 6.4 AI 修订备份与恢复（硬性）

| 规则 | 说明 |
| --- | --- |
| 何时备份 | **每一次 AI 写回开始前**（含流式），将当前正文保存为一版 revision |
| 备份内容 | 至少完整 `body_md`；若本版引用了随后可能被替换的资源，恢复策略以保证「恢复后所见与备份时一致」为准（实现可选：备份时拷贝当时 assets 快照，或恢复时按 md 引用解析） |
| 用户操作 | 提供「恢复上一版 / 从修订历史恢复」入口（文档菜单或工具栏） |
| 保留策略 | 至少保留最近 N 次 AI 修订（建议 N≥10，或按容量）；用户手动保存不强制写入该备份链（编辑器 Undo 另算） |
| 与物理删除 | 文档物理删除时，同步删除其 `_revisions/{note_id}/`（避免孤儿备份） |

## 7. API 草图（实现前写入 API_CONTRACT）

> 以下为产品级契约意向，正式字段以日后 `API_CONTRACT.md` 为准。

```text
GET    /api/notes/tree                    # 目录树 + 各节点下文档摘要
POST   /api/notes/folders                 # 创建文件夹 { name, parent_id? }
PATCH  /api/notes/folders/{id}            # 重命名 / 改 parent_id（移动）/ sort_order
DELETE /api/notes/folders/{id}            # 删除文件夹（策略见确认点）

GET    /api/notes                         # 扁平列表（可选；树接口为主）
POST   /api/notes                         # 创建 { title?, folder_id? }
GET    /api/notes/{id}                    # 详情（含 body_md）
PATCH  /api/notes/{id}                    # 更新 title / body_md / folder_id
DELETE /api/notes/{id}                    # 删除文档
```

**Agent 工具（仅记事本侧边；主对话不暴露）：**

```text
notes_get          # 读 note_id 的 title + body_md（或摘要）
notes_apply_edit   # { note_id, op, content_md, selected_text? }
                   # op ∈ replace_selection | insert_at_cursor | append | replace_document
```

目录 CRUD **不**作为本期 Agent 工具（避免 AI 乱动用户结构）；用户在 UI 自行维护。

- 查找/替换（人工）：**优先前端在已加载正文上完成**（无需专用搜索 API）。  
- 划词侧边：复用现有 chat / aside 创建与 SSE 契约；扩展允许 `from_note`。  
- 若未来做跨文档搜索，再增 `GET /api/notes/search?q=`。

冲突策略：保存时若服务端 `updated_at` 较新，返回 409，前端提示「文档已在别处更新」并提供重新加载 / 覆盖（覆盖需二次确认）。AI 写回与自动保存争用时，以工具写回结果为一次完整 PATCH，并刷新前端 `updated_at`。

**前端实时性（写回可见）：** 工具执行成功后，需让打开中的 `NotesView` 立刻应用新 `body_md`。实现可选：① 工具结果经 SSE/事件总线通知前端 ② 侧边与笔记页共享 store，写回后 `notesApi.get` 刷新。产品要求是「用户不用手动刷新就能看到 AI 写入」。

## 10. 验收标准（可测试）

1. **新建**：点新建 → 列表出现新项 → 写入若干带格式内容 → 刷新页面 → 内容与样式仍在。  
2. **改名**：改标题 → 列表与顶栏同步 → 刷新后标题仍为新名。  
3. **删除**：删除后列表消失且文件不在 `data/notes/`；确认框可取消。  
4. **查找**：在长文中查找关键字，能跳转上一个/下一个，计数正确。  
5. **替换**：替换一处与全部替换结果正确，Undo 可恢复。  
6. **标题**：可设置并切换 H1–H6，保存再打开层级正确。  
7. **列表嵌套**：有序、无序分别嵌套到第 10 级可保存再打开；第 11 级无法再升且有提示。  
8. **样式**：粗/斜/下划线开闭正确，可叠加（如粗+斜），往返 md 不丢。  
9. **划词侧边**：在笔记正文划词 → 浮条出现 → 侧边会话 → 选区进入侧边引用/输入区且**不自动发送**；再次划词追加到同一侧边；侧边内无「再开侧边」；关闭后前端不残留；`/chat` 原有划词侧边行为回归通过。  
10. **AI 流式写回**：侧边要求改写 → 编辑区流式出现内容 → 写前有备份 → 「恢复」可回到 AI 改前 → 刷新后为写回后内容。  
11. **插图**：插入/粘贴图片 → 保存再打开仍可见；md 中为引用、文件在 assets。  
12. **目录**：新建多级文件夹 → 把文档移入 → 刷新后树结构仍在；重命名文件夹不影响文档正文与图片；删非空文件夹须确认，确认后子文档与子文件夹一并物理删除（可取消）。  
13. **主对话**：调用不到笔记写回工具。  
14. **回归**：不影响 `/chat` `/memory`；Langfuse 同轮无旁路第二条 trace。

## 11. 风险与对策

| 风险 | 对策 |
| --- | --- |
| MD ↔ 富文本往返丢样式（尤其下划线、嵌套列表） | 选定编辑器后做往返测试集；下划线用稳定扩展 |
| 10 级列表在部分序列化器被拍平 | 实现时用用例锁深度；失败则改存储为结构化 JSON + md 导出（保底，非首选） |
| 自动保存与多端/多标签冲突 | P0 单页单编辑者 + updated_at；P2 再加强 |
| 范围蔓延成迷你 Word/N++ | 严格按 §2 / §9；新需求进 P2 清单 |
| GPL | 不引入 N++/NotepadNext 代码与语言包 |
| `/notes` 与 `/chat` 侧边状态串扰 | 绑定键分离（session vs note）；抽屉可见性按路由切换；单测/手测切换路由 |
| AI 写回与用户同编冲突 | P0「AI 编辑中」锁；完成后解锁并刷新 |
| 模型胡写整篇覆盖 | `replace_document` 默认受限 + 确认；常用 op 限于选区/光标/追加 |
| 选区在 WYSIWYG 中与 MD 偏移不一致 | 写回以「当前编辑器选区」为准由前端应用，或工具返回 MD 片段由前端按选区替换，避免纯字符 offset 对不齐 |
| 物理目录镜像导致移动碎图 | 采用逻辑 `_tree.json` + 稳定 `note_id` 路径（§6.2） |
